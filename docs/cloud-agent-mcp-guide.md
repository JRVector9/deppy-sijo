# 클라우드 에이전트의 Deppy 세션 사용

Deppy에서 사용자가 공유한 원래 터미널 세션의 입력과 출력을 사용한다. 연결한 에이전트는 자신의 최종 답변을 `notify`로 그 세션에 남긴다. 답변은 해당 세션의 로컬 이력과 알림 센터에 저장된다. 터미널 stdin에 답변을 쓰지 않는다. 설정의 **에이전트 작업 지시문 복사**는 이 계약을 공통 지시문으로 제공한다. 제공자별 실제 계정 인증 상태는 [연결 안내의 호환성 표](cloud-agent-mcp.md#제공자-호환성과-실제-계정-검증)를 확인한다.

1. `list_sessions`에서 공유된 `session_id`와 `generation`을 보관한다. `input_allowed`는 사용자 입력 허용과 OAuth 입력 범위를 함께 반영한다. `paste_bracketed`는 현재 관측한 DEC 2004 모드이며, `paste_ai_confirmed`는 AI 실행 정체성이 확보되어 있는지 보여준다. 이 값들은 관측값이다. 입력 시 다시 검사한다.
2. `read_output`으로 최근 관측된 화면을 읽는다. `lossless:false`, `may_be_stale:true`를 고려한다. `screen:null`은 캐시가 같다는 뜻이다. 새 출력이 없다는 증거나 턴 완료 신호가 아니다. `retry_after_ms` 뒤 다시 읽고 반환된 cursor를 사용할 수 있다. 신뢰할 수 있는 턴 완료 경계나 stdout 전체 로그를 제공하지 않는다.
3. 단일 줄 수동 입력은 기존 `send_text`를 사용한다. 본문 최대 8192 UTF-8 바이트이고 개행·탭·ESC·제어문자를 거부한다. `submit` 기본값은 false이며 true일 때만 Enter를 붙인다. 기존 공유 셸·대화 상자의 승인된 수동 입력 계약을 유지한다. `send_ctrl_c`는 승인된 원래 세션에 Ctrl+C를 한 번 보낸다.
4. 여러 줄 프롬프트 또는 의도적인 붙여넣기는 `paste_text`를 사용한다. `submit` 기본값은 false다. LF, CRLF, 탭은 확인된 bracketed paste 모드에서만 허용하며 CRLF는 LF로 정규화된다. 한글과 이모지는 UTF-8로 보존한다. 단독 CR, ESC 및 나머지 제어문자는 거부한다. 모드가 꺼져 있을 때 한 줄 일반 텍스트는 수동 입력으로 허용하며, 여러 줄이나 탭은 거부한다. 알려진 AI의 실행 정체성이 확인되지 않으면 거부한다.
5. 답변을 마치면 **자신이 작성한 최종 답변**으로 `notify`를 호출한다. 분석만 하고 터미널에 입력하지 않았어도 필요하다. 처음 보관한 원래 session_id/generation을 사용한다. 탭을 전환해도 다른 세션에 보내지 않는다. 저장이 시작된 답변의 완료는 연결을 중지한 후에도 원래 세션에 반영된다.

## 붙여넣기 예

```json
{
  "name": "paste_text",
  "arguments": {
    "session_id": "<list_sessions의 원래 UUID>",
    "generation": "<원래 generation>",
    "operation_id": "<이 작업의 고유 ID>",
    "text": "첫째 줄 😀\r\n둘째 줄\t설명",
    "submit": true
  }
}
```

본문은 최대 32768 UTF-8 바이트다. 직렬화한 arguments와 전체 HTTP JSON 본문은 각각 65536 바이트 이하여야 한다. 큰따옴표·역슬래시 등의 JSON 이스케이프와 요청 봉투 때문에 본문 한도 전에 거부될 수 있다. 전체 HTTP 한도는 기존과 같다.

`submit:true`는 본문과 별도 Enter 하나를 하나의 PTY 큐 예약으로 입장시킨다. 일부 본문만 입장하거나 거부된 본문 뒤에 Enter만 보내지 않는다. 확인된 AI 세션에 기존 입력 초안이나 선택/승인 대화 상자가 있으면 새 프롬프트 제출을 거부한다. `submit:false`는 의도적으로 기존 초안에 붙일 수 있지만 대화 상자에는 자연어 붙여넣기를 보내지 않는다. 모드·원래 실행·세션·허용권·인증·마감 시간은 비동기 이력 claim 뒤와 실제 큐 입장 경계에서 다시 확인한다.

`status:"queued"`는 PTY 큐 입장 확인이며 AI 실행 또는 완료 확인이 아니다. `completion:"not_confirmed"`를 그대로 해석한다. 동일 operation_id는 정확히 같은 도구와 arguments에만 재사용한다. `unknown`은 자동으로 다시 보내지 않는다. 새 ID를 만들어 재시도하면 이중 실행될 수 있다. Deppy는 보이지 않는 새 AI 프로세스를 만들어 이 요청을 수행하지 않는다.

```json
{
  "name": "notify",
  "arguments": {
    "session_id": "<원래 UUID>",
    "generation": "<원래 generation>",
    "operation_id": "<답변 저장 작업의 고유 ID>",
    "message": "연결한 에이전트가 직접 작성한 최종 답변"
  }
}
```

`notify`는 최대 16384 UTF-8 바이트다. 입력 허용이 없어도 읽기 공유가 유지된 원래 세션으로 답변을 저장할 수 있다. 공유·인증이 이미 취소되거나 요청이 만료됐다면 새 저장 요청은 거부된다. 성공 응답은 이력 저장 완료 이후에 반환된다.

## 연결별 권한과 작업 보고

새 커넥터는 인증한 연결별로 사용자의 명시적 읽기·입력 승인을 받아야 한다. 토큰 발급·인증·도구 호출 성공은 서로 다른 상태다. `list_sessions`에 원하는 세션이 없으면 권한을 넓히려고 임의의 세션 ID를 추측하지 말고 사용자에게 해당 연결의 읽기 공유를 요청한다. 읽기만 허용된 연결은 입력 제어권을 받을 수 없다. 이전 공유 Bearer의 여섯 도구 계약은 유지되며, 아래 관리 도구와 `run_id`는 추가 계약이다.

1. `start_run`에 원래 `session_id`, `generation`, 고유 `run_id`, 작업 `title`과 선택적 `instruction`을 보내 클라우드 작업을 등록한다. 등록·`queued`는 실행이나 완료 증거가 아니다. 인증한 연결의 ID는 서버가 정하며 인자로 다른 작성 주체를 만들 수 없다.
2. 승인된 입력이 필요하면 `acquire_control`로 같은 세션·실행·선택적 작업의 임시 제어권을 받는다. `ttl_seconds`는 1–120초다. 다른 연결이나 같은 연결의 다른 작업이 제어 중이면 인계를 기다린다. 사용자가 제어를 회수하면 대기 입력도 차단되므로 다시 승인받기 전까지 입력을 중단한다.
3. `send_text`, `paste_text`, `send_ctrl_c`, `notify`에 선택적 `run_id`를 넣어 작업과 수신증을 연결한다. 기존 도구의 UTF-8 한도, `submit` 기본값과 동일 `operation_id` 규칙은 그대로 적용된다.
4. `update_run`으로 `running`, `waiting`, `completed`, `failed` 등 자신의 단계와 heartbeat를 보고한다. `progress`는 0–100의 **에이전트 보고값**이며 로컬 터미널 관측과 구분된다. 오래된 보고나 재시작 후의 `unknown`을 완료로 취급하지 않는다. `get_run`과 `list_runs`로 서버에 저장된 상태와 취소 요청을 확인한다.
5. 사용자의 취소 요청을 확인한 에이전트만 `update_run`의 `state:"cancelled"`로 취소를 인정한다. 취소 요청, 입력 권한 회수, `send_ctrl_c`는 각각 다른 동작이다. 터미널이 조용하다고 임의로 취소·완료를 보고하지 않는다.
6. 작업을 마치면 `update_run`의 결과·결과물과 함께 기존 `notify`로 **자신의 최종 답변을 원래 세션에 저장**한다. 다른 활성 탭으로 결과를 보내지 않는다. 결과물 참조는 실제 생성·확인한 HTTP(S) 링크만 보내며 최대 16개다. `release_control`은 자신의 같은 세션·실행·작업 제어권만 해제한다.

`instruction`은 최대 8192, 진행 `message`는 최대 4096, `result`는 최대 16384 UTF-8 바이트다. 도구 탐색에서 반환된 최신 스키마와 한도를 우선 확인한다.

## 유실 응답과 출력 이력

입력 응답이 유실되면 `get_operation`에 원래 세션·실행과 동일 `operation_id`를 보내 **읽기 전용 수신증 조회**를 먼저 한다. 다른 연결의 수신증을 조회하거나, 다른 세션의 권한으로 원래 세션의 수신증을 열 수 없다. 수신증이 없거나 `unknown`이어도 새 ID로 자동 재실행하지 않는다. `queued`는 PTY 큐 접수, `stored`는 답변 저장을 뜻하며 클라우드 작업 완료는 별도 보고다.

현재 화면 이전의 오류나 긴 작업 출력은 `read_history`로 읽는다. 원래 세션·실행, cursor와 `max_bytes`(최대 65536)를 사용하며 reset·truncated 표시와 관측 시각을 확인한다. 등록 비밀을 가린 제한된 터미널 관측 이력이며 클라우드 작업 완료의 자동 판정 근거는 아니다. 응답의 재조회 간격을 지키고 무제한 폴링을 하지 않는다.

## 프로필과 재인증

설정의 연결 프로필에는 이름·로컬 포트·공개 호스트·자동/고정 주소 방식만 저장한다. 토큰·승인·공유 입력 권한을 저장하거나 자동 복원하지 않는다. 프로필을 불러오려면 현재 서버 연결을 먼저 중지한다. 임시 자동 주소가 바뀌면 외부 커넥터의 URL도 갱신해야 한다.

일시 장애 뒤의 제한된 재연결은 사용자가 켠 경우에만 시도한다. 명시적 연결 중지나 인증 만료 후에는 자동으로 권한을 되살리지 않는다. 커넥터에서 인증을 다시 시작하고 Deppy의 요청 목록에서 새 요청을 승인한 뒤 세션별 권한을 재확인한다. Mac 잠자기·앱 종료 중 터미널 접근은 중단되며, 다시 연결해도 결과가 불명확한 입력을 재전송하지 않는다.
