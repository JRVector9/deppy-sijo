## 2. 이번 세션에서 한 일

### 작업(fleet) 화면 한 목록 개편 — 이번 세션의 주 작업

사용자 지적: "작업화면 두개로 분리하는 의미가 없어. 세션화면만 나와도 될거같은데."

- 「지금 처리」 좌측 컬럼과 `render_hero`를 없앴다. 세션 목록만 전체 폭으로 그린다.
- 「막힌 것」 묶음 맨 위에서 **가장 오래 막힌 항목 하나만** 그 자리에서 펼쳐
  승인·거부·입력 응답을 바로 한다(`render_expanded`).
- 「건너뛰기」·「다음 대기」와 `FleetUi.skipped` 상태를 없앴다. 다음 항목이 바로 아래
  카드로 보이므로 넘길 이유가 없다.

핵심 계약은 순수 함수로 뺐다(`crates/app/src/ui/fleet.rs`):

- `BlockedItem.session: Option<BlockedRef>` — 큐 항목이 가리키는 세션.
  `BlockedRef::Pty { workspace_id, session }` 또는 `Structured { session_id }`.
  `SessionId`는 워크스페이스마다 재사용되므로 **반드시 쌍으로** 식별한다.
- `blocked_rows(queue, blocked_sessions) -> Vec<BlockedRow>` — 큐와 세션 카드를
  **한 번씩만** 잇는다. `Expanded(0)`(맨 앞 항목, 그 세션 카드는 뺀다),
  `Card(slot)`(카드가 있는 뒤 항목), `Compact(i)`(카드가 없는 결정 — 승인 세션 키를
  못 읽은 경우), 그다음 큐에 없는 막힌 세션이 카드로 붙는다.
- 회귀 테스트: `막힌_묶음은_같은_막힘을_두_번_그리지_않는다`.

지켜낸 기존 계약 두 가지를 깨뜨리기 쉬우니 주의한다.

1. **큐가 비어도 `waiting_ui.render`를 매 프레임 호출한다** — 안에서 stale 입력버퍼를
   정리한다(2026-07-17 P2). 조기반환으로 건너뛰면 버퍼가 남는다.
2. **세션이 0인데 승인만 남으면 펼친 카드와 「세션 없음」 안내가 함께 보여야 한다.**
   처음 구현에서 조기반환을 넣었다가 `세션이_없어도_승인_카드는_그린다`가 잡아냈고,
   안내를 목록 **끝**으로 옮겨 고쳤다.

`FleetPageOutput`의 필드는 바뀌지 않았다 — `app.rs` 쪽 배선은 그대로다.

### 함께 담긴 이전 작업들

- **서브에이전트 기본값은 opus / high.**
- **UI·디자인 변경은 테스트가 아니라 화면으로 검증한다** (프로젝트 `CLAUDE.md`).
  빌드+재기동이 첫 액션이고, 게이트는 커밋 직전에 한 번만 돌린다. 로직·wire 계약·storage
  같은 화면 밖 동작에는 이 예외를 적용하지 않는다(기존대로 테스트 먼저).
- **작업 흐름**: 별도 worktree, PR 단위 단일 커밋, 병렬 서브에이전트 리뷰,
  `gh pr merge --rebase`. force-push 같은 파괴적 단계는 확인 후 진행한다.

## 6. 이 기계에서 겪은 함정

- **스왑 포화**: 35.8GB 중 34.8GB 사용, 로드 13 상태에서 `rustc`가 CPU 0%로 멎는다.
  샌드박스 문제가 아니다. 빌드가 멈춘 것처럼 보이면 `ps`로 상태를 먼저 본다.
- **`pkill -f "cargo test ..."` 금지**: 래퍼 셸의 명령줄에 그 패턴이 들어 있어 자기
  자신을 죽인다. **pid로 죽인다.**
- **죽은 cargo의 파이프를 붙든 `tail`**: cargo를 죽여도 파이프 뒤의 `tail`이 살아남아
  체인 전체가 멈춘다. 그 `tail`도 함께 죽여야 한다.
- **`cargo fmt` 뒤 앵커 소실**: 포맷이 앵커 줄을 재배치해 문자열 치환이 조용히 실패한
  적이 있다. 편집 후에는 테스트로 실제 적용을 확인한다.
