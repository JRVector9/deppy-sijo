항목현재수정 제안
기존 키 수정파일에서 가져온 키는 API 목록에서 제외됨. 환경 목록의 행은 표시/삭제만 제공. 수동 API는 편집 가능한 행을 더블클릭해야 수정.출처가 달라도 한 목록에 표시. 모든 로컬 키에 수정 버튼. 파일 원본이면 해당 파일을 바꾸고 보관값 갱신. GitHub App 클라이언트 시크릿과 개인키(.pem)도 종류별로 보관.
키 복사값은 그린 텍스트. 키 영역의 복사 동작이나 별도 복사 버튼 없음.키 값 더블클릭, 명시적 복사 버튼. 숨김을 유지한 채 실제 값을 복사. 잠금/미보관 상태는 사유 표시.
자동 갱신선택된 환경파일 → dotenv 프로필/Keychain 갱신은 있음. 활성 파일 트리 watcher와 실행 준비 경로에 연결. 수동 API binding이 파일 값보다 우선할 수 있음.프로젝트별 원본과 우선순위를 명시. 파일 트리와 분리된 변경 추적. 모드별 환경파일과 PEM 파일 연결, 누락·잠금·실패·충돌 상태 유지.
빌드 사용새 shell/agent 환경 전달은 있음. 기존 프로세스의 환경을 자동으로 교체하지 않음. 빌드별 최신값 확인/사용 버전 기록은 없음.연결한 명령을 감싼 실행 경로에서 최신값 검사 → 빌드 자식 프로세스에 주입 → 사용 버전 기록. 기존 터미널 명령에는 wrapper 연동.
GitHub Secret프로젝트 키 보관과 별개로 Actions Secret 목적지 연결·업데이트 기능을 확인하지 못함.정확한 저장소/Repository·Environment·Organization 범위와 이름을 연결. 등록 시 자동 전송 여부 선택. 실패 재시도와 외부 변경 알림.

GitHub에서 바꾼 키를 자동으로 읽어 올 수는 없습니다

GitHub App 개인키는 발급할 때 받은 PEM 파일을 보관해야 합니다. GitHub는 공개 부분만 보관하므로 새 개인키가 생기면 그 파일을 연결하거나 가져오는 경로가 필요합니다. GitHub App 개인키 공식 문서

GitHub API는 Secret의 이름과 변경 시각을 반환하고 값을 반환하지 않습니다. 앱이 보관한 값은 전송할 수 있지만, 외부에서 교체한 값은 새로 입력하거나 읽을 수 있는 원본 파일에 반영해야 합니다. “전송 완료”와 “원격 값 동일”을 구분합니다. GitHub 공식 API 문서

사용 계약

  • 빌드를 실행했다고 키를 임의로 교체하지 않습니다. 빌드 전 최신값을 확인하고, 실제 원본이 바뀔 때 보관값을 갱신합니다.
  • 에이전트가 파일의 키를 수정해도 동일한 파일 변경 경로로 감지합니다. 터미널 출력이나 대화에서 비밀값을 추측해 수집하지 않습니다.
  • GitHub 인증용 토큰과 GitHub에 저장하는 Actions Secret을 서로 다른 역할로 표시합니다.
  • 프로젝트 빌드용 키와 에이전트 인증 전달 범위를 분리합니다. 기존 API 연결의 의미를 자동 변경하지 않습니다.
  • 복사는 기본 숨김을 유지합니다. 실제 앱에서는 임시로 읽고, 30초 뒤 앱이 복사한 값이 남아 있을 때만 클립보드를 지우는 선택 기능을 제공합니다.
  • 파일 삭제·비어 있음·Keychain 잠금·전송 실패 시 마지막 정상 보관본과 상태를 보존합니다. 최신 확인 실패를 저장 성공으로 표시하지 않습니다.

구현 순서 · PR별 완료 기준

기존 Keychain 저장·논리 ID 교체·원본 파일 쓰기 기능을 재사용합니다. 아래는 구현 제안이며 제품 반영은 아직 하지 않았습니다.

PR 1 · 가장 먼저

통합 목록 + 수정 + 복사

환경/API의 로컬 키를 출처와 함께 표시. 파일 원본 행도 수정. 값 영역 더블클릭과 버튼 복사, 이름 영역은 상세 보기. 클릭 영역 분리와 잠금 오류 표시.

완료 기준: 기존 nomorevibe형 dotenv 키 수정·복사, 수동 API 수정, 빈 수정값=유지, 새 키 교체 후 논리 ID 유지, 다른 프로젝트 접근 차단.

PR 2

프로젝트 원본과 변경 자동 보관

파일 경로/변수명/모드/원본 우선순위를 명시. GitHub App 개인키는 PEM 파일로 연결하고 클라이언트 시크릿과 구분. 활성 화면과 무관하게 등록된 프로젝트만 감시. 원자적 파일 교체·대량 저장·잠자기 복귀 재검사와 충돌 처리를 포함.

완료 기준: 외부 편집·에이전트 편집·inactive 프로젝트·앱 재시작에서 최신값 보관. 파일 누락/잠금/실패에서 정상본 보존, 프로젝트·개발/운영 격리.

PR 3

빌드 연결과 사용값 기록

프로젝트의 명령을 등록하거나 wrapper로 실행. 실행 직전 원본 재검사, 동일 버전 snapshot을 자식 프로세스에 전달. 키 이름/버전/사용 시각만 기록.

완료 기준: 오래된 shell에서 시작해도 연결한 빌드는 최신값 사용. 실행 중 빌드 값은 유지. 미설정 명령/필수 키 누락/출처 충돌 사유 표시. 에이전트 인증과 분리.

PR 4

GitHub Secret 목적지 연결

사용자가 지정한 저장소와 범위에 암호화 전송. 로컬 보관 버전과 전송 완료 버전 분리. 앱 종료 후 재시도 가능한 작업 큐, 최신 교체 순서 유지, 권한 실패 표시.

완료 기준: 저장소·Environment·Organization 대상 혼동 없음. 권한 부족/네트워크 실패/외부 변경 감지. 원격 값 미보관 상태에서 복사·가져오기 불가 사유 표시. GitHub는 원격 compare-and-swap을 제공하지 않으므로 동시 외부 쓰기를 원자적으로 막았다고 주장하지 않음.

PR 5

회귀 harness + 사용자 시나리오 검증

가짜 keyring·임시 프로젝트·fake GitHub 서버로 저장 실패, 늦은 응답, 재시도, 프로젝트 전환, watcher 중복 이벤트를 재현. 실키 없이 로그/DB/HTML에 비밀값이 남지 않는지 확인.
