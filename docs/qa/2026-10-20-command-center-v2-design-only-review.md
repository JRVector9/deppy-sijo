### D01 — 네이티브 작업자 버튼

승인 HTML 최종 CSS의 `.worker-actions button`은 높이 28px이다. 네이티브는 `workers.rs:381`에서 `interact_size.y = 28 * scale`을 지정하지만, 바로 아래 작업 상세/승인/결과 버튼을 `small_button`으로 만든다. 잠금된 egui 0.36.1의 `widgets/button.rs:306–309,339–342`는 small일 때 최소 interact 높이 적용을 건너뛰고 상하 패딩도 0으로 만든다. 따라서 옆의 일반 터미널 버튼과 높이도 다르다. 기존 실제 egui 렌더 `native/main-1440-dark-font100.png`에서 차이를 확인했다. 이번 리뷰에서 네이티브를 다시 실행하거나 새로 렌더한 것은 아니다.

### D02 — 네이티브 MAIN/CHECK 타이포그래피

시안의 최종 `.thread-entry h2`는 데스크톱 14px / 모바일 13px, 설명은 12px 및 muted 색상이다. 네이티브 `title()`은 17px를 공통 적용하며, MAIN 요약은 `ui.label` 기본 Body 14px/text 색상으로 그린다. 값은 `mod.rs:734–738`에서 확인했다. 1440px 및 390px 기존 렌더에서도 MAIN 제목과 설명이 더 크고 밝다. 데이터 문장 차이나 OS 글꼴 안티앨리어싱을 결함으로 세지 않았다.

### D03 — PWA 좌측 독립 작업 탐색 누락

승인 시안 `renderAgents()`는 각 프로젝트의 `tasks`를 표시하고, 항목 클릭 시 정확한 프로젝트/작업 상세를 연다. 제품 PWA `renderLeft()`는 작업 수만 표시하고 목록은 `p.sessions`에서만 만들며, 클릭 시 원문 터미널로 이동해 Command Center를 접는다. `p.tasks`에 3개, `p.sessions`에 메인 1개가 있는 동일 내용 fixture에서 작업 세 개 대신 메인 한 개만 보이는 것은 이 렌더 분기의 결과다. 원문 세션 목록이 항상 작업 목록과 동일하다고 가정할 수 없고 원격 작업에는 로컬 PTY가 없을 수 있다. 우측 패널과 작업 화면의 접근 경로가 없다는 뜻은 아니다. 좌측의 승인된 탐색 UX가 누락된 것이다.

### D04 — PWA 헤더/컨텍스트 배치

시안은 프로젝트 헤더에 `작업할 프로젝트`, 선택기, `프로젝트 설정 ↗`, 작업자 접기 아이콘을 둔다. 모바일에서는 선택기를 숨기고 설정 텍스트를 남긴다. MAIN 컨텍스트에는 데스크톱 `전체 기록`이 있다. 현재 PWA는 모바일에도 선택기를 노출하고 설정은 `⚙`만 표시하며, 접기는 컨텍스트로 옮겼고 `전체 기록` 바로가기는 만들지 않는다. 390px에서 선택기 display는 시안 `none`, 구현 `block`; 설정 버튼은 시안 32px, 구현 34px로 실측했다. 이력 자체가 사라진 것은 아니며 상단 이력 탭은 유지된다.

### D05 — PWA 입력창

동일 Chrome fixture에서 실제 포커스를 활성화해 blur/focus를 측정했다.

| 1440px | 62 → 100px | 68 → 68px | none | vertical |
| 390px | 60 → 88px | 68 → 68px | none | vertical |

프로젝트 메인의 전송 대상도 시안은 `nomorevibe / 메인 Codex`, 구현은 `메인 · Codex`다. 작업 대상에서는 시안의 역할·기기 대신 제목/프로바이더를 표시한다. 라우팅이 잘못된다는 주장이 아니라, 입력 바로 옆에 승인된 식별 정보를 동일하게 표시하지 않는다는 디자인 지적이다. 상단 프로젝트 헤더는 존재한다.

### D06 — PWA 담당자 열

시안 `.outline-row .owner`는 시작 정렬, 왼쪽 1px 구분선과 안쪽 패딩을 사용한다. 구현은 `text-align:right`, 구분선 0px이다. 1440px와 390px 모두 computed style과 기존 렌더로 확인했다. 설명 문구의 길이가 달라진 것을 비교한 것이 아니다.

### D07 — 작업 상세의 통합 작업/결과 구조

승인 `taskScreen()`(HTML:84–90)은 `작업과 결과 → 원문 터미널 → Git 변경 → 기록`이며, 제출된 결과·검증 근거·사용자 확인은 작업 본문 아래에 표시한다. 네이티브 `main.rs:420–425`는 작업/결과/Git/기록/터미널을 별도 탭으로 만들고, 결과는 `DetailTab::Result` 분기에만 표시한다. PWA `command-center.js:396–407`도 작업/결과/Git/기록 탭과 터미널 버튼을 제공하며 결과 전용 분기로 반환한다. 모니터 결과 바로가기는 존재하므로 결과가 사라지거나 접근 불가능하다는 뜻은 아니다. 승인된 화면 정보 구조가 바뀐 것이다. 이 항목은 코드 대조로 확인했으며 현재 턴에서 새 상세 화면 캡처를 생성하지 않았다.

### D08 — PWA 설정의 기본/고급 분리와 취소

승인 `settingsScreen()`(HTML:95)은 추론 강도·동시 실행 한도·작업 에이전트·자동화·worktree를 기본 닫힌 `details.rules`에 묶고 저장/취소를 나란히 둔다. 현재 PWA는 같은 필드들을 `fields`에 직접 추가하며 저장 버튼만 만든다(`command-center.js:482–495`). 네이티브의 실행 규칙 접힘과 취소는 이미 존재하므로 이 지적은 PWA에만 해당한다. 복원 시 실제 초안을 처리하는 정책은 호스트 계약을 보존해야 하며, 시안의 메모리 fixture 저장 방식을 제품에 복사하라는 뜻은 아니다.

### D09 — 네이티브 모바일 탭의 글꼴 축소

승인 최종 모바일 CSS는 주요 탭 11px와 `primary-nav` 가로 스크롤을 유지한다. 네이티브는 원래 11px × font_scale을 계산한 뒤, `mod.rs:1122`에서 가용 폭/전체 텍스트 폭의 비율을 다시 곱한다. 공간이 부족하면 글자가 작아지고 확대 설정 일부도 상쇄된다. 담당 에이전트가 390px 기본/1.25배 기존 렌더를 대조했고 root도 해당 계산을 확인했다. OS 타이틀바의 좌측 76px 예약 공간 자체는 결함으로 세지 않았다.

### D10 — 네이티브 프로젝트 행 정렬

승인 프로젝트 행은 왼쪽 glyph, 그 옆 이름, 오른쪽 count로 구분한다. `workers.rs:72–80`은 이름과 개수를 하나의 문자열로 만들어 전체 폭 가운데 정렬 버튼에 넣는다. 기존 1440px 렌더에서 프로젝트 이름 옆에 개수가 붙고 좌측 glyph가 없는 차이가 보인다. 행 높이 34px의 적용과 별개로 내부 정렬이 다르다.

낮은 우선순위 보조 메모: PWA MAIN 흐름은 시안의 선 연결·현재 독립 실행 단계 강조 대신 muted 화살표 텍스트를 사용한다(`command-center.js:331–332`, CSS:11). 핵심 발견 수에는 별도로 추가하지 않았다.

## 확인된 반영 사항과 검증 범위

- 프로젝트/메인/우측 작업자의 큰 구조, 다섯 상단 목적지, 반응형 1050/760px 전환, 네이티브 62px 배정 행, 작업자 고정 하단 기기 영역, 설정 620px 폼/36px 필드는 코드 및 기존 근거에서 확인했다.
- 승인 HTML/spec/원본 PNG 총 **6/6 SHA-256**가 reference.json과 일치했다. 네이티브 기존 캡처의 UI 소스 **8/8 SHA-256**도 현재 소스와 일치했다.
- root가 이번에 직접 연 캡처: approved/shared/native MAIN 1440px dark 각 1장, 390px dark 각 1장, 총 6장. 네이티브 담당은 추가 1280px/1000px/390px 확대·drawer 캡처, 보조 화면 담당은 기존 설정·기기 캡처도 열어 대조했다. 모두 이전에 생성된 fixture 렌더이며 사용자의 현재 실행 앱 캡처가 아니다.
- 이번에 새로 실행한 브라우저 실측: 승인 시안/PWA × 1440/390px, 네 케이스의 blur/focus, 선택기 표시, 헤더 버튼, 입력 대상, 담당자 정렬·테두리, 화면 폭. 모든 측정에서 문서 폭은 viewport와 같았다. 출력은 [browser-measurements.json](assets/command-center-v2-design-only-20261020/browser-measurements.json)에 보존했다.
- 첫 측정에서는 headless document focus가 비활성이라 시안 focus 높이도 그대로 보였다. `Emulation.setFocusEmulationEnabled`를 활성화하고 전 케이스를 다시 실행해 최종 JSON을 교체했다. 최초 수치는 근거로 사용하지 않았다. 보조 manifest 확인 중 `files`를 객체로 간주한 진단 스크립트의 AttributeError도 목록 형태로 다시 읽어 바로잡았다.
- 현재 턴에서 Cargo/전체 workspace/150개 브라우저 회귀 테스트를 새로 실행하지 않았다. 이 보고서는 기존 기능 검증 결과를 재실행한 것으로 주장하지 않는다. 백엔드/실제 에이전트/사용자 데이터/실기기 E2E를 검증하는 리뷰가 아니다.

제품 소스는 변경하지 않았다. 수정이 별도로 요청되면 D01–D10을 네이티브/PWA 파일 소유권으로 분리하고, 승인 HTML을 수정하는 대신 제품 렌더를 맞추는 것이 다음 단계다.
