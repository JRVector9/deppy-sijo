## PR1 — 메인 관리 도구와 실제 MAIN 기록

새로 시작하는 로컬 Codex MAIN에 프로젝트 전용 MCP 연결을 등록한다. 프로젝트·작업 조회, 계획안 제출, 사용자가 확인한 로컬 작업 배정, 원래 요청의 처리 결과 조회를 제공한다. 계획 확인과 최종 완료 확정 권한은 사용자에게 남는다. 일반 공유 연결·워커·다른 프로젝트는 이 권한을 얻지 않는다.

현재 메인의 프로젝트·런타임·실제 프로세스·세대·설정·목표를 확인한다. 대기열, 저장 완료, 지연된 입력, 실제 프로세스 생성까지 권한을 다시 검사하고 회수 가능한 permit을 전달한다. 중복 요청은 원래 결과를 돌려주며, 실행 여부가 불명확하면 자동으로 다시 실행하지 않는다.

연결 토큰은 메모리에만 보관하고 런타임에는 일회용 불투명 참조를 전달한다. 실제 resolver가 실행 직전에만 해석한다. MCP 주소 설정은 transient 인자로 전달하므로 세션 재개용 인자에 남지 않는다. 메인 전용 프로필을 포함한 전체 런타임 프로필 상한은 32개다.

MAIN에는 실제로 접수한 입력, 정확한 메인에서 관찰한 최종 응답, 관리 도구의 실제 처리 상태를 표시한다. 사용 가능한 structured 기록도 정확한 연결 소유권을 확인한 뒤 투영한다. 제목·요약을 대화처럼 만들어 표시하지 않는다. PTY 경로의 전체 실시간 출력은 원래 터미널에서 확인한다.

대화 수·문자열·총 전송량을 제한하고, 완전한 원본을 마스킹한 뒤 화면 길이를 제한한다. 잘린 캐시 조각은 새로 등록된 키에도 다시 마스킹한다. 키 마스킹 목록이 바뀌면 별도 작업 이벤트가 없어도 PWA 캐시를 갱신한다. 새 프레임 생성 실패 시 민감해진 이전 캐시는 비운다.

## PR2 — 명시적인 로컬 명령 검증과 실행 증거

네이티브 작업 결과에서 명령·폴더·시간·출력 제한을 직접 확인한 뒤 실행한다. 폴더 확인과 descriptor 고정은 기존 bounded worker에서 처리하고, 호스트는 준비 결과가 현재 작업과 여전히 같은지 확인한 뒤 실행을 허용한다. UI 스레드에서 폴더 확인·DB·프로세스 실행을 하지 않는다.

검증 증거는 작업·시도·결과 revision·원본/산출물 식별자와 정확한 명령에 결합한다. 실행 전 Running, 결과 전달 전 최종 증거를 sidecar에 저장한다. 종료 코드·stdout/stderr·시간 초과·출력 잘림·취소·시작 실패를 구분하며 출력은 마스킹 후 제한한다. 동일 경로의 폴더가 바뀌는 경우에도 다른 폴더에서 실행하지 않도록 열린 descriptor를 고정한다.

설정·대상·원본·폴더가 바뀌거나 취소되면 이전 결과를 통과 처리하지 않는다. 저장된 이력을 불러오는 행위는 명령 재실행이나 현재 결과의 자동 승인으로 이어지지 않는다. 사용자 직접 검증 기록은 앱 실행 증거와 분리한다. 실행 검증이 통과해도 최종 완료는 사용자 확인을 기다린다. PWA는 실행 증거만 조회한다.

## 리뷰에서 수정한 문제와 실패 접근

- 원래 메인 binding 소실, 오래된 실제 프로세스 허용, 대기 중 배정·입력의 권한 회수를 수정했다.
- 실제 resolver 테스트가 토큰을 논리 자격 증명 ID로 잘못 전달하는 실행 실패를 재현했다. 메모리 참조로 바꾸고 실제 셸 전달을 검증했다. 임시 주소가 세션 인자에 저장되는 문제도 transient 인자로 수정했다.
- 잘린 텍스트에서 키 일부가 남는 문제, 새 키 등록만으로 원격 캐시가 갱신되지 않는 문제, 마스킹 후 응답 크기가 증가하는 문제를 실제 실패 테스트로 확인하고 수정했다. fragment 마스킹을 모든 문자열에 적용하는 접근은 ID·상태를 훼손할 수 있어 화면용 필드에만 한정했다.
- 동기 폴더 확인을 비동기 준비 단계로 옮겼다. 새 키 등록으로 수동 증거 문구가 바뀌어도 불변 식별자로 응답을 연결하고, 다른 식별자는 명시적으로 거절한다.
- 최초 root compile의 잘못된 설정 필드명, 프로세스 identity를 route와 따로 바꾼 fixture, Claude 설정을 상속한 Codex 프로필 fixture를 수정했다. 이들은 제품 회귀의 RED로 계산하지 않는다. 초기 strict lint의 3건도 수정 후 전체 lint를 다시 통과했다.
- 원격 전송 로그의 마지막 빈 줄이 diff 검사를 실패시켰다. 읽기용 복사본만 정리하고 정확한 원본은 deterministic gzip과 해시로 보존했다.

## 검증 범위와 다음 작업

유료·실제 에이전트 모델 turn, 물리 휴대폰 E2E, 앱 재실행·배포는 수행하지 않았다. 자동 등록은 새 로컬 Codex MAIN 대상이다. PR3–PR6의 원격 자동 배정·자율 루프 등으로 범위를 확대하지 않았다.

프로세스 정리는 소유한 일반 자식 process group을 대상으로 한다. 의도적으로 별도 session으로 분리한 daemon의 격리는 제공하지 않는다. 비정상 앱 종료 후 Interrupted 이력은 관찰 중단을 뜻하며, 과거 자식의 종료를 증명하거나 명령을 다시 실행하지 않는다.

이번 요청의 코드 구현·리뷰·통합 검증은 완료했다. 이후 사용용 앱을 빌드·제공할 때는 다른 worktree의 마지막 배포 버전까지 확인해 버전을 올리고, 실행 요청이 새로 있을 때만 앱을 재시작해야 한다.
