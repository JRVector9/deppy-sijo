# MCP 자동 연결 검토 — 설치가 없는 사용자 기준

날짜: 2026-09-27
상태: 최초 검토 뒤 사용자 교정에 따라 자동 임시 MCP 연결을 구현했다. 구현·검증 결과는 `2026-09-27-automatic-mcp-connect.md` 참고. 아래 비교 및 관리 게이트웨이는 최초 설계 검토 내용이다.
검토 소스: `/Users/jr/Desktop/projects/deppy-sijo-performance`, 제품 코드 `5e30a4f1`, 문서 HEAD `09e031bc`.

## 요구사항

- 사용자는 Tailscale, cloudflared, Homebrew를 설치하지 않고도 Deppy에서 연결할 수 있어야 한다.
- Cloudflare 계정이나 개인 도메인이 없는 사용자도 지원한다.
- MCP 연결 버튼에서 주소 준비, 연결 상태 확인, 재연결, 종료를 관리한다.
- 기존 터미널의 입력/출력 및 Grokbot 자체 답변 수신을 사용한다. 새 LLM/로컬 에이전트를 자동 실행하지 않는다.
- 사용자가 터널 터미널을 유지하거나 매번 주소를 입력하는 흐름을 없앤다.
- Cloudflare 서비스를 사용할 수 없는 환경도 별도 연결 경로로 지원해야 한다. 프로그램 미설치와 서비스 접근 불가는 다른 조건이다.

## 비교

| 방식 | 사용자 설치·계정 | 주소 유지 | 개발/운영 부담 | 판단 |
|---|---|---|---|---|
| Deppy 관리 MCP 게이트웨이 + 앱의 내장 연결 | Deppy 외 터널 설치/Cloudflare 계정 불필요 | 기기 등록을 유지하는 동안 고정 주소 | 공개 HTTPS 서버 운영과 HTTP MCP 브리지 개발 필요 | 일반 사용자용 권장 구조 |
| 앱에 포함한 cloudflared로 자동 임시 터널 | 사용자 별도 설치·Cloudflare 계정 불필요 | 터널 프로세스 재생성 시 무작위 주소 | 실행 파일 동봉/서명, 자식 프로세스·주소 탐지·복구 관리 | 빠른 초기 구현 및 임시 연결 경로 |
| 개인 Cloudflare 고정 터널 또는 Tailscale Funnel | 초기 계정/도메인 또는 Tailscale 환경 필요 | 해당 호스트를 유지하는 동안 고정 주소 | 기존 환경 탐색·선택 기능 | 고급 사용자의 선택 기능 |

Cloudflare Quick Tunnel은 계정/사이트 등록 없이 무작위 주소를 생성할 수 있으며, 공식적으로 시험/개발용이다. SSE 미지원이나 현재 Deppy MCP는 HTTP POST JSON 응답이며 GET SSE를 제공하지 않으므로 그 제한만으로 현재 전송이 불가능하다고 판단하지 않았다. 실제 공개 Grokbot 연결 성공은 이번 조사에서 검증하지 않았다. [공식 Quick Tunnel 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

개인 Cloudflare 고정 터널에는 공개 애플리케이션의 도메인/경로 설정이 필요하다. 앱이 사용자에게 도메인 구매를 요구하는 흐름을 기본으로 두지 않는다. [공식 설정 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/)

Tailscale Funnel은 tailnet DNS를 사용하고, `--bg` 구성은 재부팅/재연결 후 유지될 수 있다. 그러나 Tailscale 환경 자체가 필요하므로 설치가 없는 사용자의 기본 해법은 아니다. [Funnel 설명](https://tailscale.com/docs/features/tailscale-funnel), [CLI의 재시작 동작](https://tailscale.com/docs/reference/tailscale-cli/funnel)

## 권장 사용자 경험

기본 메뉴는 `MCP 연결하기` 하나로 둔다. 고급 연결 방식은 별도 설정으로 접는다.

1. 연결하기를 누르면 `주소 준비 중 → 연결 확인 중 → 연결됨` 상태를 표시한다.
2. Deppy 관리 연결이 구성돼 있으면 앱의 내장 클라이언트가 외부 HTTPS 중계에 나가는 연결을 생성하고 고정 MCP 주소를 받는다. 여기서 제안하는 관리 MCP 서비스는 현재 제공 중인 것으로 주장하지 않는다.
3. 임시 연결을 선택하면 앱에 포함한 cloudflared를 직접 실행한다. Terminal.app 창, Homebrew 실행, 전역 설치가 필요하지 않다. 공개 주소와 MCP 인증 base를 함께 확정한 뒤 주소 복사를 활성화한다.
4. Grokbot에 주소를 등록하고 OAuth 승인을 진행하거나 현재 수동 토큰을 등록한다. 연결과 입력 권한은 분리하고 기존 세션 공유·입력 허용·입력 회수를 유지한다.
5. Grokbot은 `read_output`으로 원래 세션 화면을 읽고, 허용된 `send_text`로 입력하며, `notify`로 자신의 답변을 원래 세션의 기록/알림에 전달한다.
6. 연결 끄기에서는 MCP 인증/대기 입력을 먼저 회수한다. 앱이 생성한 터널만 종료하고 직접 설치된 외부 서비스/다른 사용자의 터널은 건드리지 않는다.
7. 재시작 후 방식/주소 설정은 복원한다. 입력 권한을 자동으로 다시 허용하지 않는다. 현재의 휘발성 MCP 인증을 유지한다면 재인증이 필요하다는 점을 UI에 명확히 표시한다. 로그인까지 영속화하려면 별도의 인증 저장/회수 설계를 포함해야 한다.

자동 임시 터널만으로는 주소 재등록 문제가 끝나지 않는다. 이를 자동으로 처리한다고 약속하려면 Grokbot에 등록된 주소를 변경할 수 있는 공식 인터페이스를 확인해야 하며, 이번 제안은 그런 인터페이스가 있다고 가정하지 않는다.

## 구현 경계와 검증 계획

- 터널 관리: App의 작업 스레드와 작은 연결 상태 기계가 담당한다. 터미널 세션의 stdin이나 에이전트 런처로 터널 명령을 보내지 않는다.
- 동봉 실행 파일: OS/아키텍처에 맞는 고정 버전 실행 파일을 빌드 시 검증·동봉·서명한다. 앱 실행 때 무조건 Homebrew/관리자 권한 설치를 시도하는 흐름은 사용하지 않는다.
- 초기 주소 확보: 현재 Server의 허용 호스트는 고정된다. 시작 순서를 분리하거나 허용 호스트/인증 base를 함께 갱신하는 API를 마련해야 하며, UI만 바꾸는 수정으로 끝내지 않는다.
- 준비 완료 기준: 터널 URL 로그를 발견한 것과 실제 MCP가 접근 가능한 것을 구분한다. 공개 metadata/응답 확인 실패, 포트 점유, offline, 만료는 명시적인 상태로 표시한다.
- 프로세스 수명: 중복 클릭, 시작 중 취소, 타임아웃, 예기치 않은 종료, 앱 종료를 검증한다. stderr/stdout은 제한된 크기로 계속 소비하며 앱이 소유한 PID만 관리한다.
- 게이트웨이: 기존 암호화 Relay를 평문 HTTP 경로로 바꾸지 않는다. 별도의 HTTP MCP 입구와 승인된 앱 연결을 이어야 하며 서버 비용/모니터링/배포가 필요하다. 터미널 출력·입력 저장이나 오프라인 명령 큐는 추가하지 않는다.
- 인증/세션: 기존 UUID+generation, 권한 입장 검사, 입력 회수, operation_id 중복 방지, PTY 수신증, 답변 기록을 그대로 검증한다. 재연결 시 결과가 불명확한 입력을 재실행하지 않는다.
- 핵심 완료 기준: 외부 도구 없는 환경에서 버튼 연결, 원래 터미널 입력→출력 읽기, Grokbot 자체 답변 수신, 탭 전환 후 대상 고정, 연결 끄기 후 입력 거절. 공개 계정 검증은 로컬 모의 검증과 구분한다.

## 후속 구현 상태 (최초 검토 해석 교정)

- 앞선 응답은 검토·보고 요청에 치우쳐 버튼 자동 연결 구현 의도를 놓쳤다. 사용자의 교정 후 별도 설계 승인을 다시 요구하지 않고 구현했다.
- 신규 기본값은 동봉한 검증된 cloudflared로 자동 임시 주소를 생성하는 방식이다. Tailscale, cloudflared, Homebrew의 사용자 설치나 Cloudflare 계정이 필요하지 않다. Cloudflare 서비스 접근이 막힌 환경은 수동 고정 HTTPS 호스트를 통한 다른 공급자 경로를 사용한다. 공급자 독립 관리 게이트웨이는 이번 구현에 포함하지 않았다.
- 기존 호스트/포트 설정은 이미 App에서 저장·복원하고 있었다. 생성자의 초기값만 보고 저장 기능이 없다고 했던 최초 판단을 정정한다. 새로운 자동/수동 모드는 기존 저장 경로에 추가하며, 이전 고정 호스트 설정은 수동 모드로 이관한다.
- 공개 주소 생성, 실제 공개 MCP 입력→PTY 출력 읽기 및 봇 자체 답변 수신 테스트를 실행했다. 실제 Grokbot 계정의 커넥터 연결 인증은 별도이며 테스트 통과를 주장하지 않는다.
- `AGENTS.md`의 필수 버전 증가 규칙에 따라 신규 기능 버전을 0.1.0에서 0.2.0으로 올렸다. 재빌드와 동봉 도우미 서명·패키지 검증을 진행하며 사용자 앱은 재실행하지 않는다. 상세 최종 결과와 정확한 커밋/명령은 후속 구현 보고서에 기록한다.
