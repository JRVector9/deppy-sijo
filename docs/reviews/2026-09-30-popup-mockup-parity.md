# 0.4.4 팝업과 승인 HTML 시안 비교

- 범위: 01 워크스페이스 추가의 GitHub 입력 화면, 02 새 폴더, 03 새 파일.
- 기준: `docs/mockups/shared-popup-components-2026-09-30.html`의 CSS와 해당 사례, `docs/design/popup-components.md`.
- 실행 증거: 현재 실행 중인 Deppy에서 세 팝업을 직접 열어 접근성 트리와 스크린샷을 확인했다. 파일 생성, Git 복제, 설정 저장은 실행하지 않았으며 비교용 팝업은 닫았다. 이 요청에 실제 첨부 이미지 데이터는 전달되지 않아 현재 실행 화면을 확인했다.
- 최초 검토 상태: 당시에는 수정 목록 작성만 완료했으며 제품 코드와 실행 프로세스를 변경하지 않았다. 아래는 이후 사용자 승인에 따른 적용 기록이다.

## 0.4.5 컴포넌트 수정 적용

7개 항목을 `ui/popup/` 공용 컴포넌트에서 수정하고 사례 01–03에 연결했다. 개별 화면은 입력 초안과 기존 작업 의도를 계속 소유한다.

| 항목 | 적용 | 검증 근거 |
| --- | --- | --- |
| 입력 | `text_input`, 36pt 높이, 세로 8pt/가로 10pt 여백 | 실제 GitHub 양식의 세 입력 높이 19pt → 36pt; 생성 창 렌더 하네스도 36pt 검증 |
| 버튼 | 34pt 높이, 좌우 13pt, 8pt 간격, Ghost 취소 | 실제 양식의 취소 여백·버튼 사이 간격 테스트 통과 |
| 경로 행 | `path_input`, 실측 버튼 너비 제외, 7pt 간격, 중앙 정렬 | 오른쪽 미사용 공간 약 32.7pt → 0pt; 입력/버튼 중앙 정렬 검증 |
| 선택 탭 | 선택 회색 배경과 테두리, focus 표시 | 실제 한국어 워크스페이스 팝업 PNG 확인; 양방향 탭 클릭 테스트 통과 |
| 안내 | 본문 전체 폭, 정보/오류 별도 팔레트 | 실제 렌더 이미지에서 입력 오른쪽과 안내 박스 오른쪽 일치 확인 |
| 레이아웃 | 닫기 독립 배치, 1pt 구분선, 명시적 간격, 높이 예산 | 280×360 양식의 y=-14..373 넘침을 재현한 뒤 화면 내부 유지 검증 |
| 글자/힌트 | 레이블·주 버튼 강조, URL 형식, 지원 단축키 지역화 | 다섯 언어 키 추가, i18n 8/8; 하단 힌트의 실제 글자 위치 정렬 검증 |

실제 앱 컴포넌트를 `egui_kittest`와 wgpu로 화면 밖에서 렌더링했다. 앱을 재실행하지 않았다. 이미지: `target/popup-parity/01-workspace.png`, `02-folder.png`, `03-file.png`.

중간 검증에서 버튼 실측 너비의 올림으로 0.7pt 간격이 남고, footer 라벨의 글자만 가운데 정렬되는 문제를 발견해 수정했다. 전체 테스트는 탭 전환 후 이전 모달 크기에 제한되어 매 프레임 59pt씩 커지는 문제도 잡았다. 본문 크기 계산을 이전 영역 크기와 분리하고 모달 크기 변경 후 중앙 위치를 안정시켜 기존 클릭 테스트를 통과시켰다. 최종 전체 검사와 배포 빌드 결과는 `docs/CODEX_HANDOFF.md`에 기록한다.

## 적용 순서와 검증

1. `fields.rs`에서 입력 높이/여백을 직접 보장하고 `actions.rs`에서 버튼 padding, 8pt 간격, Ghost 역할을 정한다.
2. `workspace_add.rs`의 경로+찾아보기 행을 공용 제어로 연결한 뒤 탭, notice, 헤더/필드 간격을 맞춘다.
3. 세 팝업의 같은 상태를 캡처해 시안과 비교한다. 기존 폭/넘침/Enter/Esc 테스트 외에 TextEdit 바깥 높이, 버튼 padding/간격, 경로 행 끝 정렬을 harness에서 확인한다. 좁은 화면과 긴 경로도 확인한다.

기존 `workspace_add.rs:863` 테스트는 모달 너비를 검사하며 입력 높이나 버튼 padding은 검사하지 않는다. 이번 검토에서는 테스트를 새로 실행하지 않았다.
