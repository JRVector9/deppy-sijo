## 조사 기준

현재 작업 대상인 `/Users/jr/Desktop/projects/deppy-sijo-performance`의 소스와 [42개 HTML 사례](../mockups/shared-popup-components-2026-09-30.html), [공용 디자인 계약](../design/popup-components.md)을 대조했다. 기준은 실제 `ui/popup` 표시 셸·확인창·필드·푸터 사용 여부다. 기존 창에서 공용 Esc 처리나 입력 보호 함수만 사용하는 것은 디자인 적용으로 세지 않았다.

이 작업은 소스 조사와 문서 정리다. 앱 UI를 실행해 새로 검증하거나 테스트·재빌드·버전 변경·재실행·종료·커밋·푸시하지 않았다. 현재 소스는 0.5.4이며, 이전에 실행된 0.5.3과 구분해야 한다. 미적용은 디자인 이전 상태이며, 이번 조사로 각 기능의 동작 오류를 발견했다는 뜻은 아니다.

## 포트 팝업은 존재한다

- **포트 관리 목록:** 하단 상태바의 포트 표시를 클릭하면 `agent_terminal.rs:538`에서 앵커 팝오버를 연다. `ports.rs:53`의 목록은 현재 워크스페이스·다른 워크스페이스·외부 프로세스 섹션, 갱신, 주소 복사, 종료 버튼을 표시한다. 외부·보호·소유권 불명확 프로세스는 읽기 전용으로 표시한다. 이 목록에는 공용 모달 셸이 적용되지 않았다.
- **포트 점유 프로세스 종료 확인:** 목록의 종료 버튼으로 대상을 저장하고 `ports.rs:236`의 `popup::confirmation`을 호출한다. **시안 12번이며 공용 확인창 적용 완료**다. 원래 목록 팝오버가 닫혀도 확인 대상은 유지한다.
- 시안 **37번**은 승인·리소스·포트를 하나의 간략한 상태 예시로 묶었다. 따라서 포트 기능이 없는 것이 아니라 **포트 관리 목록의 독립적인 상세 시안이 없는 상태**다. 12번은 그 목록 전체가 아니라 종료 확인창이다.
