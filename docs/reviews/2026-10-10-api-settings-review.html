01 / CURRENT IMPLEMENTATION

환경설정에서 제공하는 기능

환경 및 API 화면의 프로젝트 목록에서 대상을 선택하고, 환경변수 표 아래의 API 키 영역을 사용합니다.

현재 구현되어 있는 것

키 추가·숨김/표시·수정·삭제, 프로젝트의 환경변수 이름 연결, 연결 해제, Keychain 고아 항목 정리가 구현되어 있습니다. API 키의 값과 연결 이름을 함께 저장하거나 수정할 때 DB 변경은 한 트랜잭션으로 처리합니다.

키 보관과 프로세스 전달은 구현되어 있지만, 이 등록 경로에는 공급자에 실제 요청을 보내는 인증 테스트가 없습니다.

구분해서 이해해야 하는 것

공급자·종류는 보관 항목의 정보입니다. 환경변수 이름이 실제 프로그램에 전달되는 이름이며, 프로그램이 그 이름을 읽어야 사용됩니다.

Codex의 사용자 지정 LLM 연결은 에이전트 세션 설정에 있는 별도 기능입니다. API 키 표에 OpenAI 키를 넣는 것만으로 Codex의 모델 공급자·주소·인증 방식을 자동 변경하지 않습니다.

현재 화면 기준으로 안내합니다. 공급자 선택 드롭다운이 있는 신형 화면도 코드에 남아 있지만, 현재는 classic 화면을 사용하도록 고정되어 있습니다. 이 보고서의 사용법은 직접 확인한 공급자/라벨/종류/비밀키 표를 기준으로 합니다.
02 / HOW TO USE

API 키 등록부터 적용 확인까지

  1. 환경설정을 열고 프로젝트 선택

    ⌘ + , → 환경 및 API → 적용할 프로젝트를 선택합니다. 환경변수 표가 길면 아래로 스크롤해 API 키 영역을 찾습니다.

  2. API 키의 ‘+ 추가’ 선택

    공급자와 라벨을 직접 입력하고, 종류를 api_key 또는 token으로 선택합니다. 현재 화면에서는 공급자·라벨·비밀키가 모두 있어야 추가가 가능합니다.

  3. 실제 환경변수 이름을 지정

    OpenAI SDK용이라면 OPENAI_API_KEY를 입력합니다. 비워 두면 키만 보관되며 실행 환경에 연결되지 않습니다. 비밀키에는 공급자가 발급한 실제 값을 넣습니다.

  4. ‘추가’ 후 적용 상태 확인

    목록에 저장된 항목이 나타나는지 확인합니다. 상단의 환경 준비 상태는 새 실행에 전달할 환경의 준비 상태이며, 공급자 인증에 성공했다는 뜻은 아닙니다.

  5. 해당 프로젝트에서 새 세션으로 확인

    새로 시작하는 셸·에이전트가 변경된 환경을 받습니다. 이미 실행 중인 에이전트의 환경변수는 자동으로 바뀌지 않습니다. 필요하면 해당 에이전트를 새로 실행합니다.

04 / EDIT, DISCONNECT, DELETE

저장한 키를 관리하는 방법

수정 · 새 키로 교체

API 키 표에서 해당 행을 더블클릭합니다. 현재 프로젝트가 소유한 api_key/token 항목을 수정할 수 있습니다.

수정 화면의 비밀키 입력을 비워 두면 기존 값을 유지합니다. 새 값을 넣으면 Keychain의 새 physical slot으로 교체하고 논리 ID는 유지합니다. 다른 환경·MCP 참조를 새 항목으로 다시 연결할 필요가 없습니다.

공유/다른 소유 범위의 키는 목록에서 보이더라도 동일하게 수정할 수 있는 것은 아닙니다.

환경 연결을 나중에 지정하거나 해제

API 표 아래 Agent 환경 연결 영역을 펼칩니다. 해당 항목의 환경변수 이름을 입력하고 저장하면 연결됩니다.

이름을 빈칸으로 지우고 저장하면 해당 프로젝트의 API 환경 연결이 해제됩니다. 비밀키 자체는 보관됩니다. 이미 실행 중인 프로세스가 받은 키는 그대로일 수 있습니다.

삭제 전에 사용 중인 연결부터 해제합니다. API 환경 연결, 일반 환경변수의 credential 참조, MCP의 credential 참조가 남아 있으면 삭제가 거절됩니다. 현재 UI는 이 이유를 구분하지 못해 일반 실패만 보여줍니다. 연결을 해제한 뒤 행의 ×와 삭제 확인을 사용하세요. Deppy에서 삭제하는 것은 로컬 보관 항목 삭제이며, 공급자 계정에서 발급 키를 폐기하는 작업은 별도입니다.
‘고아 키 정리’는 언제 쓰나요?

DB의 현재 참조와 분리된 Keychain/physical slot을 정리하는 복구용 기능입니다. 일반적인 사용 중 키 삭제를 대신하지 않습니다. 참조가 정상인 키의 삭제 제한을 우회하는 용도로 안내하면 안 됩니다.

05 / DATA AND EXECUTION

코드에서 실제로 처리하는 순서

설정 입력→Keychain 비밀값+DB 메타정보·연결→프로젝트 실행 환경 준비→새 프로세스 시작 전 값 해석·출력 가림 등록→프로세스 환경 전달

유지해야 할 구현

비밀키 값은 Keychain에 저장하고, SQLite에는 메타정보·마스킹 힌트·참조 포인터를 저장합니다. 키와 binding의 DB 변경은 트랜잭션으로 처리합니다. 수정·삭제는 기대한 physical pointer와 일치하는지 검사하여 오래된 작업이 새 키를 지우지 않도록 합니다.

실행 전에는 필요한 키 전체를 읽고 출력 가림 lease를 먼저 확보합니다. 키를 읽지 못하거나 가림 등록이 실패하면 일부 값만 전달하지 않고 실행을 거절합니다. 이 보호를 유지하고, 잘못된 연결을 저장 전에 찾도록 개선해야 합니다.

동일한 환경변수 이름의 우선순위

새 에이전트 실행 시 다음 순서로 합쳐지며 뒤쪽 값이 우선합니다.

프로젝트 일반 환경→프로젝트 비밀 환경→프로젝트 API 연결→실행별 일반 환경→실행별 비밀 환경

API 연결은 같은 이름의 .env 값을 덮을 수 있습니다. 실행별 override가 있으면 다시 달라질 수 있으므로 ‘키가 저장됨’과 ‘이 세션에 적용됨’을 구분해야 합니다.
