# 작업 화면 한 목록 main 이관 계획

**목표:** 사용자가 PR #146 실행 화면에서 확인한 작업 화면 한 목록 UI를 최신 main에 독립적으로 이관하고 미사용 번역 키를 함께 제거한다.

**범위:** `ui/fleet.rs`의 큐·세션 결합과 렌더링, 다섯 로케일의 더 이상 쓰지 않는 `fleet.hero.now/next/clear/skip/sessions` 삭제만 포함한다. Relay와 다른 #146 변경은 포함하지 않는다.

## 계약

- 가장 오래 막힌 항목 하나만 목록 맨 위에서 펼친다.
- 펼친 항목이 가리키는 세션 카드를 같은 묶음에 다시 그리지 않는다.
- 세션이 0이고 승인만 있어도 펼친 카드와 「세션 없음」 안내를 함께 그린다.
- 큐가 비어도 `waiting_ui.render`를 매 프레임 호출해 stale 입력 버퍼를 정리한다.
- 좁은 창에서 펼친 카드가 available width를 넘지 않는다.
- `fleet.hero.approval`, `fleet.hero.needs_input`, `fleet.blocked_for`는 계속 유지한다.

## 실행

1. `origin/main..75bf2c9`에서 `ui/fleet.rs`만 hunk 그대로 이관한다.
2. 다섯 로케일에서 미사용 키 다섯 개를 같이 제거하고 코드 참조 0건을 확인한다.
3. fleet 집중 테스트와 i18n 검사를 실행한다.
4. 변경 파일 대상 strict Clippy, fmt, diff, boundary를 한 번 실행한다.
5. 읽기 전용 코드 리뷰에서 확인된 결함만 수정하고 영향을 받은 검사를 재실행한다.
6. handoff와 작업 일지를 기록한 뒤 main 대상 독립 PR을 게시한다.

앱 빌드·재실행은 하지 않는다. 화면 동작은 #146 실행본에서 사용자가 이미 중복 없음, 승인 단독 빈 상태, 좁은 창 표시를 확인했으며 막힌 실제 항목의 한 개 펼침은 데이터 부재로 아직 실화면 미확인이다.
