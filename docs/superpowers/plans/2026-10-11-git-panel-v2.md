**Goal:** `docs/mockups/git-panel-redesign-2026-10-11.html` 시안을 제품 Git 보조 탭에 PR 단위로 적용해, 지금 무엇을 보고 있는지·파일 상태·브랜치 상태를 한눈에 읽게 하고 키보드와 경로 동작으로 바로 쓸 수 있게 한다.

## 0. 작업 흐름(사용자 확정 규칙)

- PR마다 `origin/main` 기준 별도 worktree에서 작업한다. 사용자 체크아웃과 `deppy-sijo-performance`의 미커밋 파일은 건드리지 않는다.
  `git_panel.rs`, `diff_viewer.rs`는 2026-10-11 기준 `origin/main`과 `deppy-sijo-performance`가 같다. i18n 파일은 다르므로 **행 번호가 아니라 키로** 편집한다.
- PR 하나 = 커밋 하나(리뷰 반영은 amend). 머지는 `gh pr merge --rebase`, 머지 후 브랜치·worktree 정리.
- 시안 HTML과 이 계획 문서는 기능 PR에 섞지 않는다(PR 0, 문서 전용).
- UI 변경은 빌드로 확인하고, 테스트·clippy·i18n-check는 커밋 직전에 한 번 돌린다. 앱 재실행은 사용자가 그 작업에서 요청했을 때만 한다.

### 1.1 병렬 실행 순서 (2026-10-11 사용자: 서브에이전트 병렬, 오케스트레이터가 충돌 관리·리뷰·커밋)

PR 1·2·3은 같은 목록 렌더 영역을 차례로 다시 쓰므로 동시에 돌리지 않는다. 파일 소유를 나눠
웨이브로 진행하고, 뒤 웨이브는 앞 웨이브 커밋 위에 쌓는다(stacked branch).

| 웨이브 | 병렬 작업 | base | 겹치는 곳(오케스트레이터가 rebase 때 해소) |
|---|---|---|---|
| 1 | PR 1 / PR 4(커밋 목록 — 현재 섹션 배치의 「브랜치 커밋」 아래에 표시) | origin/main | `GitPanelUi` 필드, `render`의 `let Self {..}` |
| 2 | PR 5(PR 1 위에서 시작) / PR 2(PR 4 위에서 시작) | 웨이브 1 커밋 | `GitPanelAction` 끝, App의 액션 match 끝 |
| 3 | PR 3 | PR 2 커밋 | — |

실제 쌓인 순서(2026-10-11): `PR 1 a27713ae → PR 4 572dca9d → PR 5 0ea33bad → PR 2 → PR 3`.
PR 4를 PR 1 위로 rebase하면서 파일 행을 `file_row` 하나로 모았다(섹션·커밋 파일 공용, PR 5의
우클릭 메뉴도 이 함수 안에 있다). 이후 PR은 파일 행을 `file_row`로만 그린다.

서브에이전트는 자기 worktree에서 구현·테스트까지만 하고 커밋하지 않는다. 오케스트레이터가
diff를 리뷰하고 고친 뒤 PR당 커밋 하나로 남긴다. push·PR 생성·머지는 사용자 요청 시에만.

PR 2~5는 착수 시점의 코드로 각자 상세 계획(`docs/superpowers/plans/<날짜>-git-panel-v2-prN.md`)을 다시 쓴다. 앞 PR이 바꾼 코드 위에서 정확한 코드를 적어야 하기 때문이다. 아래 §3은 그 계획이 지킬 범위와 수용 기준이다.

/// 목록용 폴더 표시 — 끝 두 단계만 남기고 앞은 「…/」로 줄인다. 300pt 목록에서
/// 앞부분부터 잘리면 `crates/…`만 남아 같은 저장소의 파일끼리 구분되지 않았다
/// (2026-10-11 시안). 전체 경로는 행 hover와 diff 헤더에 그대로 있다.
fn short_dir(dir: &str) -> std::borrow::Cow<'_, str> {
    let mut parts = dir.rsplitn(3, '/');
    match (parts.next(), parts.next(), parts.next()) {
        (Some(last), Some(second), Some(_)) => format!("…/{second}/{last}").into(),
        _ => dir.into(),
    }
}
```

fn status_badge_style(
    status: char,
    tokens: crate::ui::designall::Tokens,
) -> (char, egui::Color32, &'static str) {
    match status {
        'M' => ('M', tokens.warning, "git.status.modified"),

                let rect = response.rect;
                if let Some(fill) =
                    crate::ui::designall::row_fill(tokens, is_selected, response.hovered())
                {
                    ui.painter()
                        .set(background, egui::Shape::rect_filled(rect, 4.0, fill));
                }
                if is_selected {
                    // 사이드 레일 선택과 같은 2pt accent 레일.
                    let rail = egui::Rect::from_min_max(
                        rect.left_top(),
                        egui::pos2(rect.left() + 2.0, rect.bottom()),
                    );
                    ui.painter().rect_filled(rail, 0.0, tokens.accent);
                }
                // 접근성 이름을 rel_path로 명시한다 — kittest가 Role::Button + 이
                // 라벨로 행 전체(자식 Label이 아니라)를 정확히 겨냥할 수 있다.
                response.widget_info(|| {
                    egui::WidgetInfo::selected(
                        egui::WidgetType::Button,
                        ui.is_enabled(),
                        is_selected,
                        row.rel_path.as_str(),
                    )
                });
                if response.clicked() {
                    *selected = Some((row.rel_path.clone(), mode));
                    *action = Some(GitPanelAction::ShowFileDiff {
                        rel_path: row.rel_path.clone(),
                        mode,
                    });
                }
            }
```

## 3. PR 2~5 범위와 수용 기준

### PR 2 — 브랜치 카드와 탭

- `render`의 헤더(`ui.strong(&snap.branch)` + upstream 줄)를 카드로 바꾼다: 브랜치명 monospace, ↗(GitHub)·⟳ 버튼, 다음 줄에 `→ upstream`과 배지 `↑N 보낼 커밋`(success), `↓N 받을 커밋`(warning), 둘 다 0이면 `원격과 같음`, upstream 없음은 warning 테두리 배지 + hover 이유.
- 세 섹션(`변경 사항`/`브랜치에 COMMIT 됨`/`워크트리`)을 탭 3개(selectable 버튼 + 개수 배지)로 바꾸고 `GitPanelUi`에 `tab` 필드를 둔다. 용어는 「브랜치 커밋」으로 통일(`git.section.committed` 값 변경). 접힘 필드 3개(`*_collapsed`)는 제거한다.
- 탭 아래 합계 줄 `N개 파일 · +a −d`, 깨끗함 카드(보낼 커밋이 있으면 커밋 탭으로 가는 링크), 512 상한 잘림 배너.
- 필터 규칙 유지: 변경·커밋 탭만 거르고 워크트리 탭은 거르지 않는다. 기존 kittest(`kittest_필터는_...` 4개, `워크트리가_하나면_섹션을_숨긴다`)는 탭 기준으로 고쳐 쓰되 의미는 보존한다.
- 수용: 탭 전환 kittest, ahead/behind/업스트림 없음 3상태 렌더 kittest, 깨끗함 링크 → 커밋 탭.

### PR 3 — 탐색 효율

- 「목록 / 폴더별」 토글. 폴더별은 디렉터리 머리 행(접기, 개수) 아래 파일명만.
- 키: Git 보조 본문이 활성이고 텍스트 입력에 포커스가 없을 때만 ↑↓(목록 안 선택 이동 → `ShowFileDiff`), N/P(diff 변경 이동). 보조 검색창 포커스·IME 조합 중에는 무시한다. 입력 소유권은 08-15 스펙 §8-3(보조 본문 프레임은 터미널 owner 없음)을 따른다.
- 첫 스냅샷이 오고 선택이 없으면 첫 변경 파일(없으면 첫 브랜치 커밋 파일)을 한 번 자동 선택한다.
- 깨끗할 때 diff 영역에 요약(보낼/받을 커밋 수, 커밋 탭 안내). 마지막 커밋 정보는 PR 4 데이터가 생긴 뒤에 더한다.
- 수용: 키 이동 kittest(입력 포커스 중 무시 포함), 자동 선택 1회 kittest, 폴더별 접기 kittest.

### PR 4 — 커밋 목록 (새 수집)

- `collect_snapshot`과 같은 IO 왕복에서 `git log --format=%h%x00%s%x00%ct <base>..HEAD`를 상한(`MAX_BRANCH_COMMITS = 64`)으로 수집해 `GitPanelSnapshot.commits`에 담는다. 실패해도 스냅샷 전체를 죽이지 않는다(remote 조회와 같은 규칙).
- 커밋 펼침 시 새 `GitPanelIoRequest::CommitFiles { sha }`(`git show --numstat --name-status --format= <sha>`), 커밋 파일 클릭은 `DiffMode::Commit`(sha 포함) 추가가 필요하다 — `DiffMode`가 `Copy`라 sha는 고정 길이 배열로 둔다.
- 수용: 파서 단위 테스트(빈 출력, 상한 정확히/초과, NUL 포함 제목), temp repo 수집 테스트, 펼침 kittest.

### PR 5 — 경로 동작

- 파일 행 우클릭 메뉴와 diff 헤더 버튼: 경로 복사(`ctx.copy_text`, leaf에서 처리 가능), 세션에 경로 넣기(새 `GitPanelAction::InsertPath` → App이 파일 트리의 `SidebarAction::InsertPath`와 같은 경로로 처리), Finder에서 보기(파일 트리의 reveal 경로 재사용).
- 경로는 repo 상대 → 절대 경로 변환을 App이 `git_panel_cwd` 기준으로 한다(leaf는 상대 경로만 안다).
- 수용: 메뉴 액션 kittest, App 배선은 기존 InsertPath 테스트 패턴으로 1개.
