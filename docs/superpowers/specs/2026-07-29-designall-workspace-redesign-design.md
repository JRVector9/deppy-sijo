# DesignALL Workspace Redesign

작성일: 2026-07-29  
상태: 사용자 승인 완료  
대상 브랜치: local `DesignALL`  
기준 통합 커밋: `ab7e5a7`  
프로젝트 행 단순화 커밋: `75267ec`

## 1. 목표

Deppy Sijo의 메인 워크스페이스를 개발 도구에 적합한 고밀도 3단 화면으로 다시 설계한다.
참고 이미지의 정보 구조, 터미널 중심 분위기, 절제된 색상과 선형 아이콘은 활용하되,
구조적 영역을 카드나 둥근 섹션으로 감싸지 않는다. 배경은 하나의 연속된 표면으로 유지하고
영역 경계는 낮은 대비의 1px 선만 사용한다.

이번 설계는 기존 기능과 데이터 흐름을 보존하는 시각·레이아웃 변경이다. 세션 유지, PTY,
터미널 입력, 파일 탐색, 상태 수집, 하단 사용량 표시는 변경하지 않는다.

## 2. 확정된 사용자 요구

1. 구현은 `DesignALL` 브랜치에서만 진행한다.
2. 브랜치는 검증된 안정화 통합 결과와 Git 저장소/브랜치 부제 제거를 포함한다.
3. 메인 워크스페이스 전체를 1차 범위로 한다.
4. 진행은 네 단계로 나누고 단계마다 실제 앱을 빌드해 확인한다.
5. 카드형 섹션 대신 가로·세로 구분선으로만 구조를 나눈다.
6. 선택·호버 같은 일시적 상호작용 상태에는 제한적인 배경 강조를 허용한다.
7. 하단 상태바의 정보, 순서, 실시간 갱신 동작은 그대로 유지한다.

## 3. 범위

### 3.1 포함

- 좌측 전역 내비게이션 레일
- 프로젝트·세션 목록
- 파일/Git/터미널/MCP 탭
- 파일 트리
- 메인 탭 및 터미널 작업 영역의 외곽 구조
- 포커스 세션 입력창
- 하단 상태바의 시각 통합
- 패널 폭·높이 조절선, 내부 스크롤, 좁은 폭 대응
- 메인 화면에서 사용하는 공통 색상·간격·선·상태 토큰

### 3.2 제외

- 설정, 에이전트 실행 모달, 연결 모달의 전면 재설계
- 터미널 셀, ANSI 색상, PTY 프로토콜 변경
- 파일 트리 데이터 모델이나 Git 기능 변경
- 세션·에이전트 상태 모델 변경
- 하단 상태바 항목 추가·삭제·재정렬
- Markdown 편집기 계획 구현
- 새 아이콘 이미지나 네트워크 자산 로딩

설정과 모달은 1차 결과가 승인된 뒤 동일 토큰을 적용하는 후속 범위로 남긴다.

## 4. 구조 원칙

### 4.1 3단 앱 셸

화면은 왼쪽부터 다음 세 영역으로 구성한다.

```text
전역 내비게이션 레일 | 프로젝트·파일 사이드바 | 메인 작업 영역
```

- 전역 내비게이션 레일은 Home, Inbox, Fleet, Agents와 하단 보조 동작을 소유한다.
- 프로젝트·파일 사이드바는 프로젝트/세션 목록과 파일 도구를 소유한다.
- 메인 작업 영역은 탭, 터미널 출력, 포커스 세션 입력창을 소유한다.
- 하단 상태바는 세 영역 아래를 가로지르는 하나의 고정 행으로 유지한다.

세 영역은 배경색 변화나 외곽 카드로 구분하지 않는다. 레일 오른쪽, 사이드바 오른쪽,
헤더 아래, 탭 아래, 입력창 위, 상태바 위에 동일한 계열의 1px 선을 사용한다.

### 4.2 구조적 카드 금지 규칙

다음 표현은 구조 구분에 사용하지 않는다.

- 프로젝트별 둥근 카드
- 세션 그룹을 감싸는 채워진 패널
- 파일·터미널 섹션을 감싸는 별도 배경 박스
- 섹션별 그림자, glow, 입체 border
- 활성 탭을 감싸는 pill

다음 표현은 실제 상호작용 상태에만 허용한다.

- 선택 행의 매우 옅은 단색 배경
- 활성 프로젝트 또는 세션의 2px 이하 좌측 액센트 선
- 호버 중인 행의 일시적인 낮은 대비 배경
- 입력창, 메뉴, 팝업, 모달의 최소 테두리
- 상태·주의·실패를 나타내는 작은 점과 배지

## 5. 영역별 디자인

### 5.1 전역 내비게이션 레일

- 선형 아이콘과 짧은 한글 라벨을 세로로 배치한다.
- 선택 항목은 배경 카드 대신 좌측 또는 우측 액센트 선과 텍스트 색으로 구분한다.
- 알림 수는 기존 의미와 동작을 유지하는 작은 배지로 표시한다.
- 상단과 하단 그룹은 빈 공간으로 분리하되 별도 박스를 만들지 않는다.
- 레일은 전체 높이를 사용하고 알림·설정 같은 보조 동작은 하단에 고정한다.
- 좁은 폭에서는 라벨을 숨기고 아이콘을 유지할 수 있다.

### 5.2 프로젝트·세션 목록

- 프로젝트는 하나의 평평한 행으로 표시한다.
- 기본 정보는 `아바타 · 프로젝트명 · 상태 점/세션 수 · 펼침 아이콘`이다.
- Git 저장소명과 브랜치 부제는 표시하지 않는다.
- 프로젝트 행 사이에는 필요할 때만 낮은 대비의 가로선을 사용한다.
- 펼친 프로젝트의 세션은 아래에 들여쓰기해 부모·자식 관계를 표현한다.
- 세션 행은 상태, 이름, 에이전트/모델 보조 정보, 경과시간을 조밀하게 배치한다.
- 프로젝트 선택, 세션 포커스, 대기, 완료, 오류의 기존 의미와 액션을 보존한다.

### 5.3 파일 도구와 파일 트리

- 파일/Git/터미널/MCP는 텍스트 탭과 활성 하단선으로 표시한다.
- 탭 전체를 감싸는 카드나 활성 pill을 사용하지 않는다.
- 파일 트리는 현재 들여쓰기, disclosure, 파일 종류 색상, 컨텍스트 메뉴를 유지한다.
- 파일 선택은 둥근 카드가 아니라 행 전체의 옅은 강조로 표시한다.
- 프로젝트 목록과 파일 도구 사이에는 하나의 가로 구분선을 둔다.
- 기존 세로 높이 조절은 프로젝트/세션 상단과 파일 도구 하단 사이의 분할선으로 유지한다.
- 하단 파일 영역은 최소 50px과 내부 스크롤 계약을 유지하고, 상단 프로젝트 목록도 자신의
  영역에서 독립적으로 스크롤된다.

### 5.4 메인 작업 영역

- 상단 탭은 평평한 행에 배치하고 하단선으로 본문과 구분한다.
- 활성 탭은 상태 점, 밝은 텍스트, 얇은 활성선으로 표시한다.
- 검색, 분할, 레이아웃, 더보기 동작은 기존 기능을 유지하고 선형 아이콘을 사용한다.
- 터미널 출력 영역은 별도 카드 없이 메인 배경 위에 직접 그린다.
- 터미널 셀 렌더러, ANSI 팔레트, 선택 영역, 커서와 입력 이벤트는 변경하지 않는다.
- 포커스 세션 입력창은 실제 입력 요소이므로 최소 테두리와 아주 옅은 배경을 허용한다.

### 5.5 하단 상태바

다음 정보와 순서를 현재 구현 그대로 보존한다.

- Claude/Codex 사용량과 기간
- 세션 수
- MCP 수
- Claude, OpenAI, GitHub 서비스 상태
- 입력 대기 세션 수(0보다 클 때만)
- 현재 화면/터미널 표시
- CPU 사용률
- 앱 메모리
- 세션 메모리

상태바는 고정 높이를 유지하고 위쪽 1px 선으로만 본문과 구분한다. 항목 사이의 세로선,
상태 점, 사용량 색상, hover 상세 정보와 갱신 주기는 유지한다. 이번 작업에서 상태 조회나
메모리 계산 코드를 수정하지 않는다. 좁은 폭에서 세션 메모리를 hover 상세로 내리는 현재
compact 동작도 유지한다.

기존 모노스페이스 계열을 사용한다. 새 폰트 파일이나 런타임 다운로드는 추가하지 않는다.

## 7. 렌더링 구조

### 7.1 상태와 렌더링 분리

- 기존 `SidebarSnapshot`, workspace/session 상태, file-tree 상태와 액션 enum을 유지한다.
- 디자인 변경이 runtime command, PTY handle, storage row를 직접 소유하지 않게 한다.
- 구조 색상, 간격, 선 두께, 행 높이는 공통 디자인 토큰에서 읽는다.
- 렌더 루프에서 Git 조회, 파일 I/O, 프로세스 실행, 네트워크 요청을 추가하지 않는다.

### 7.2 컴포넌트 경계

- 전역 내비게이션 레일과 프로젝트·파일 사이드바는 시각적으로 분리하되 기존 액션 흐름을
  공유한다.
- 프로젝트 행, 세션 행, 탭, 구분선, 상태 점은 공통 painter 규칙을 사용한다.
- 현재 큰 `file_tree.rs`에 새 디자인 상수를 흩뿌리지 않는다. 공통 토큰과 순수 시각 helper는
  별도 UI 모듈로 분리하고, 상태를 가진 파일 트리 로직은 기존 소유권을 유지한다.
- 터미널 renderer 내부가 아니라 터미널 주변 shell/chrome만 수정한다.

## 8. 상호작용과 반응형 동작

- 패널 폭 조절과 프로젝트/파일 세로 분할 조절을 유지한다.
- 파일 하단 영역은 기존 최소 50px 높이와 내부 스크롤 동작을 보존한다.
- 프로젝트가 많으면 프로젝트 목록이, 파일이 많으면 파일 트리가 각각 자신의 영역에서
  스크롤된다.
- 이름 공간이 부족하면 보조 정보부터 줄이고, 아이콘·상태·주요 이름을 우선한다.
- 클릭 영역은 시각 요소보다 충분히 크게 유지해 얇은 라인 디자인이 조작성을 떨어뜨리지
  않게 한다.
- 키보드 포커스, 스크린리더 라벨, 컨텍스트 메뉴와 드래그 앤 드롭 계약을 보존한다.
- 선택과 호버는 구조 분리가 아니라 상태 피드백이므로 제한적인 배경 강조를 허용한다.

## 9. 단계별 실제 빌드 체크포인트

### D1 — 앱 셸과 전역 토큰

- 공통 배경, 구분선, 텍스트, 상태 색상 토큰을 추가한다.
- 3단 앱 셸과 하단 상태바 경계를 만든다.
- 기존 기능을 그대로 둔 상태에서 첫 앱 빌드를 제공한다.

승인 기준: 카드 없이 세 영역이 선으로 명확히 구분되고 기존 화면에 접근할 수 있다.

### D2 — 내비게이션·프로젝트·세션

- 전역 내비게이션 레일을 평평한 행 구조로 바꾼다.
- 프로젝트 카드와 세션 그룹 배경을 제거한다.
- 프로젝트/세션 선택·상태·펼침 표현을 새 토큰에 맞춘다.

승인 기준: 많은 프로젝트와 세션에서도 정보 계층이 명확하고 스크롤·포커스가 유지된다.

### D3 — 파일 도구·트리·메인 프레임

- 파일 도구 탭을 텍스트+하단선 구조로 바꾼다.
- 파일 트리 선택과 계층 표현을 평평하게 정리한다.
- 메인 탭과 터미널 주변 chrome을 라인 기반으로 통합한다.

승인 기준: 파일 탐색과 터미널 작업이 하나의 IDE 화면처럼 연결되고 PTY 동작이 변하지 않는다.

### D4 — 입력창·상태바 마감

- 포커스 세션 입력창과 주변 여백을 통합한다.
- 하단 상태바의 내용과 순서를 보존한 채 색·선·간격을 마감한다.
- 전체 밀도, 대비, 좁은 폭, 긴 이름을 최종 조정한다.

승인 기준: 참고 이미지의 전문 개발 도구 분위기를 가지면서 구조적 카드가 남아 있지 않다.

각 체크포인트는 별도 커밋으로 남긴다. 사용자 승인 전 다음 단계의 대규모 시각 변경을
섞지 않는다.

## 10. 검증

각 단계에서 변경 영역에 가장 가까운 기존 kittest를 먼저 실행하고 이후 앱 검증 범위를
넓힌다. 실제 명령은 구현 계획에서 현재 테스트 이름에 맞춰 고정한다.

최소 검증 계약:

- 프로젝트 선택·펼침·닫기·이름 변경 액션 유지
- 내비게이션 Home/Inbox/Fleet/Agents 액션 유지
- 사이드바 폭과 하단 높이 조절 유지
- 프로젝트와 파일 목록의 독립 스크롤 유지
- 파일 선택·펼침·컨텍스트 메뉴·드래그 앤 드롭 유지
- 터미널 포커스, Cmd+C, 한국어 IME 경로 비회귀
- 하단 상태바 전체 항목과 접근성 라벨 유지
- 좁은 폭과 긴 프로젝트/세션/파일 이름에서 clipping 안정성 유지
- `git diff --check`
- 앱 패키지 빌드 후 실제 macOS 앱 화면 확인

테스트나 빌드는 실제로 실행된 단계에서만 통과로 기록한다.

## 11. 성능·안정성 제약

- 렌더 경로에 새 파일·Git·프로세스·네트워크 조회를 추가하지 않는다.
- 프레임마다 성장하는 캐시나 고유 ID 기반 영구 보관 상태를 추가하지 않는다.
- 큰 그림자, blur, 다중 offscreen layer처럼 GPU 비용이 큰 장식을 사용하지 않는다.
- 터미널 viewport와 파일 트리 가상화/클리핑 정책을 완화하지 않는다.
- 상태바 갱신 주기와 사용량 수집 경로를 변경하지 않는다.
- 디자인 확인용 임시 코드나 feature flag는 최종 단계에서 제거한다.

## 12. 실패와 롤백

- 각 단계가 독립 커밋이므로 사용자 승인 실패 시 해당 단계만 되돌린다.
- 기능 회귀가 발견되면 시각 변경을 축소하고 기존 액션·상태 계약을 우선한다.
- 새 레이아웃 때문에 PTY, IME, 복사, 파일 DnD 경로 수정이 필요해 보이면 디자인 작업을
  중지하고 별도 결함으로 분리한다.
- 하단 상태 정보가 누락되거나 순서가 바뀐 빌드는 승인 대상으로 제시하지 않는다.
- `main`과 안정화 통합 브랜치는 `DesignALL` 승인·통합 전까지 변경하지 않는다.

## 13. 완료 조건

- 메인 워크스페이스가 3단 라인 기반 셸로 동작한다.
- 구조적 프로젝트 카드, 세션 카드, 섹션 박스와 활성 pill이 제거된다.
- 선택·호버·입력 같은 상호작용 요소만 제한적인 배경을 사용한다.
- 기존 프로젝트, 세션, 파일, 터미널, 입력, 상태바 기능이 유지된다.
- 하단 상태바의 항목·순서·실시간 동작이 기존과 동일하다.
- 네 번의 실제 앱 빌드 체크포인트가 사용자에게 제시되고 승인된다.
- 검증 결과와 남은 수동 확인 항목이 `docs/CODEX_HANDOFF.md`에 기록된다.
