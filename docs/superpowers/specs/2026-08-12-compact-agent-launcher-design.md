# Compact Agent Launcher Redesign

작성일: 2026-08-12  
상태: 사용자 디자인 승인 완료  
대상: `crates/app/src/ui/agent_launcher.rs`

## 1. 목표

현재 에이전트 런처의 기능과 실행 계약을 모두 유지하면서, 선택과 실행 옵션을 한눈에 읽을 수
있는 컴팩트한 2단 모달로 다시 설계한다. 일반적인 사용 환경은 감지된 에이전트가 1–2개인
경우이며, 이때 불필요한 빈 공간 없이 콘텐츠 높이에 맞춰 창이 줄어들어야 한다.

## 2. 유지할 기능

- 설치된 에이전트 감지와 수동 새로고침
- 에이전트 선택 및 선택 상태 표시
- 에이전트 카드 더블클릭 실행
- 모델 선택
- 추론 강도 또는 사고 켬/끔 선택
- 지원 에이전트의 YOLO 모드와 활성화 경고
- YOLO 미지원 상태 안내
- 빈 터미널 실행
- 세션 시작과 시작 중 상태
- 감지·중복 실행·실행 실패·선택 만료 오류 표시
- 모달 바깥 클릭 및 닫기 동작
- 다크·라이트 테마와 다국어 문자열

런처의 intent, detection snapshot, launch option, worker, runtime correlation 데이터 흐름은
변경하지 않는다.

## 3. 확정된 정보 구조

### 상단

- 제목은 `새 세션 시작`이 아니라 `세션`으로 표시한다.
- 다음 줄에 대상 프로젝트명과 에이전트 선택 안내를 표시한다.
- 제목 영역의 상하 여백은 현재보다 줄인다.

### 본문

본문은 세로 구분선으로 나눈 2단 구조다.

- 왼쪽: 설치된 에이전트 목록, 감지 상태, 새로고침
- 오른쪽: 선택된 에이전트의 모델, 추론 강도/사고, YOLO 옵션

왼쪽과 오른쪽의 비율은 정확히 50:50으로 둔다. 전체 모달은 현재 최대 폭보다 작거나 같은
컴팩트 폭을 사용하고, 좁은 화면에서는 사용 가능한 폭을 넘지 않는다.

## 4. 에이전트 목록

- 각 행은 브랜드 색의 기존 두 글자 배지와 에이전트 이름만 표시한다.
- `claude`, `codex`, `kimi` 같은 명령어 식별자 보조 텍스트는 제거한다.
- 보조 텍스트를 제거한 에이전트 이름은 행 높이의 세로 중앙에 맞춘다.
- 선택된 행은 앱 액센트 색 테두리, 선택 배경, 체크 표시로 구분한다.
- 목록은 최대 세 행까지만 보인다.
- 네 번째 에이전트부터 목록 내부에서 세로 스크롤한다.
- 에이전트가 1–2개면 목록 높이를 억지로 세 행까지 늘리지 않고 실제 행 수에 맞춰 줄인다.
- 감지된 에이전트가 없으면 기존 빈 상태와 빈 터미널 안내를 유지한다.

## 5. 실행 옵션

- `실행 설정` 섹션 레이블을 표시하지 않는다.
- 선택된 에이전트명과 배지를 오른쪽에서 다시 표시하지 않는다.
- 첫 번째 사용 가능한 필드가 패널 상단에서 바로 시작한다.
- 모델과 추론 강도는 레이블 위, 전체 폭 콤보박스 아래의 일관된 필드 구조로 표시한다.
- 모델 또는 강도 개념이 없는 에이전트는 해당 필드를 렌더링하지 않는다.
- YOLO는 얇은 구분선 아래 독립된 체크 옵션으로 둔다.
- 지원되는 경우 일반 설명은 제거하고 `경고: 안전 승인을 우회하며 샌드박스가 비활성화될 수
  있습니다.`를 옵션 아래에 항상 표시한다.
- YOLO 활성화 시 같은 경고를 두 번째 줄에 중복 표시하지 않는다.
- 미지원 에이전트 안내도 유지하되 콘텐츠 높이를 불필요하게 늘리지 않는다.

## 6. 하단 동작

- 하단 왼쪽에 `빈 터미널`, 오른쪽에 `세션 시작` 버튼을 둔다.
- 상단 우측에 표준 `×` 닫기 버튼을 두고, 실행 대기 중이 아닐 때 기존 모달 닫기 경로를
  사용한다.
- `더블클릭으로 바로 시작` 안내 문구는 표시하지 않는다.
- 더블클릭 실행 기능 자체는 유지한다.
- 실행 중에는 기존 스피너와 시작 중 상태를 표시하고 중복 실행을 막는다.

## 7. 시각 원칙

- `designall`의 다크·라이트 색상 토큰과 현재 egui visuals를 사용한다.
- 새 전역 색상이나 런타임 자산을 추가하지 않는다.
- 카드 그리드를 만들지 않고, 모달 외곽·두 패널 사이·하단 동작 영역에만 낮은 대비 선을 쓴다.
- 모서리 반경은 기존 상호작용 반경 범위 안에서 작게 유지한다.
- 본문 텍스트와 보조 텍스트의 현재 대비 체계를 유지한다.
- 그림자, 블러, 애니메이션처럼 렌더 비용이 큰 장식은 추가하지 않는다.

## 8. egui 구현 구조

- 기존 `AgentLauncherUi::show`가 모달과 상태 조정을 계속 소유한다.
- 상단, 2단 본문, 하단 동작 영역을 작은 렌더 helper로 분리해 한 함수의 중첩을 줄인다.
- 왼쪽 목록만 `egui::ScrollArea::vertical`을 사용하고 높이는 `min(실제 콘텐츠, 3행)` 규칙으로
  계산한다. 설치된 에이전트가 네 개 이상이면 동일 영역 안에서 스크롤할 수 있어야 한다.
- 오른쪽 옵션은 기존 `render_options`의 상태 변경 계약을 유지하되 컴팩트 필드 레이아웃으로
  다시 그린다.
- 콤보박스의 전체 항목 표시와 화면 경계 처리 계약은 현재 `combo_popup_height` 경로를
  유지한다.
- 렌더 경로에 새 파일, 프로세스, 네트워크 또는 설정 읽기를 추가하지 않는다.

## 9. 상태와 오류

- 감지 중에는 왼쪽 헤더에서 기존 스피너와 상태 문자열을 표시한다.
- 감지 실패는 목록 영역과 가까운 위치에서 표시한다.
- 실행 실패, busy, unavailable 오류는 실행 옵션과 하단 동작 사이에서 기존 오류 색으로
  표시한다.
- 선택된 에이전트가 새 감지 결과에서 사라지면 기존 reconciliation 규칙대로 첫 에이전트를
  선택하거나 선택을 해제한다.
- 실행 중에는 모달을 닫지 못하게 하는 현재 계약을 유지한다.

## 10. 검증과 실행

사용자가 이번 작업에서 테스트를 실행하지 말라고 명시했으므로 단위 테스트, kittest, Clippy,
전체 테스트는 실행하지 않는다. 구현 후에는 앱을 화면에 띄우기 위해 필요한 빌드와 macOS 앱
패키징만 수행한다. 빌드 결과를 테스트 통과로 표현하지 않는다.

수동 화면 확인 항목:

- 에이전트 1개와 2개에서 모달 높이가 콘텐츠에 맞게 줄어드는지
- 에이전트 3개는 모두 보이고 4개부터 목록만 스크롤되는지
- 에이전트 행에서 명령어 식별자가 사라지고 이름이 세로 중앙에 놓이는지
- 제목이 `세션`으로 보이는지
- 좌우 패널 폭이 50:50인지
- 상단 우측 `×`로 실행 대기 중이 아닐 때 닫히는지
- 오른쪽에 에이전트명과 `실행 설정`이 중복 표시되지 않는지
- YOLO 일반 설명은 사라지고 안전 경고가 항상 한 번만 보이는지
- 하단에 두 버튼만 보이는지
- 모델과 추론 강도 드롭다운이 창 밖에서 잘리지 않는지
- 다크·라이트 테마에서 선택과 보조 텍스트가 읽히는지

## 11. 범위 밖

- 런처 외 화면의 재설계
- 에이전트 종류, 모델 카탈로그 또는 실행 인자 변경
- 검색 필드와 명령 팔레트형 탐색 추가
- 새 키보드 단축키 추가
- 감지 및 실행 worker 변경
- i18n 문구의 의미 전면 개편

## 12. 완료 조건

- 런처가 컴팩트한 2단 구조로 표시된다.
- 기능과 실행 데이터 흐름은 기존과 동일하다.
- 일반적인 에이전트 1–2개 환경에서 불필요한 세로 빈 공간이 없다.
- 최대 세 에이전트가 보이고 그 이상은 목록 내부에서 스크롤된다.
- 사용자 피드백으로 제거된 제목·중복 레이블·안내 문구가 화면에 남아 있지 않다.
- 빌드한 macOS 앱이 화면에 열린다.
