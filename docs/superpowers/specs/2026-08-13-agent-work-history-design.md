# 에이전트 작업 이력 B안 설계

## 목표

현재 선택한 워크스페이스의 에이전트 작업을 사용자 지시 단위로 기억하고, 좌측 레일의 `이력` 버튼을 누르면 워크스페이스·세션·파일 패널을 그대로 유지한 채 중앙 터미널 영역에 카드 목록으로 보여준다.

## 화면 계약

- 좌측 레일에 `이력` 항목을 `작업`과 `AI` 사이에 추가한다.
- `이력`은 `Home`, `Fleet`, `Terminal`과 같은 중앙 화면 모드다. 사이드바 컴포넌트나 워크스페이스 선택 상태를 교체하지 않는다.
- 화면 헤더는 `작업과 변경`, 현재 워크스페이스명, 현재 브랜치를 표시한다.
- 기본 정렬은 `실행 중 → 확인 필요 → 최근 완료`이며 최신 갱신 시각을 2차 정렬로 쓴다.
- 카드는 사용자 지시, 현재 수행 내용 또는 마지막 에이전트 응답, 에이전트·모델·Reasoning Effort, 브랜치, 변경 파일 수, 상대 시각을 표시한다.
- 카드를 누르면 같은 카드 안에서 첫 지시와 최근 수행 내용, 실행 동작, `Git 변경 보기`가 펼쳐진다. 별도 상세 2열 패널은 만들지 않는다.
- 검색은 사용자 지시·최근 수행 내용·에이전트·모델·브랜치에 적용하고, 상태 필터는 전체·실행 중·확인 필요·완료를 제공한다.
- 워크스페이스 행을 누르면 `이력` 화면을 유지한 채 새 워크스페이스의 이력으로 전환한다. 세션 행을 누르면 터미널로 돌아가 해당 세션에 포커스한다.

## 데이터 계약

- 카드 한 장은 에이전트 프로세스 전체가 아니라 실제 사용자 지시 한 턴이다.
- 키는 `workspace_id + agent_session_id + provider turn key`다. provider turn key는 원본 이벤트의 native turn ID가 있으면 사용하고, 없으면 transcript 안의 안정적인 바이트 오프셋을 사용한다. 동일한 문구를 반복해도 서로 다른 카드가 된다.
- transcript는 기존 안전한 regular-file, symlink 거부, 줄·바이트 상한을 그대로 사용한다. 최근 소스 256개, transcript당 최근 24턴, 워크스페이스당 저장 행 256개, 결과 4 MiB를 상한으로 둔다.
- 저장 문자열은 기존 정제 함수를 거친 사용자 지시와 에이전트 요약만 사용한다. tool payload, 전체 transcript, secret, 전체 터미널 출력은 저장하지 않는다.
- 첫 릴리스의 transcript 턴 수집은 현재 안전한 파서와 바인딩이 있는 Claude, Codex, Kimi를 대상으로 한다. 저장 키와 카드 렌더링은 bounded provider ID를 사용해 Grok 등 후속 공급자를 스키마 변경 없이 추가할 수 있게 한다.
- 실행 중 최신 턴은 같은 키로 upsert해 수행 내용과 상태를 갱신한다. 오래된 턴은 완료로 고정한다.
- branch는 해당 턴을 처음 관측하거나 사용자가 새로고침한 시점에 그 cwd에서 읽어 저장한다. Git이 아니거나 detached HEAD거나 조회에 실패하면 배지를 생략한다. 과거 시점 branch를 추정해서 만들지 않는다.
- 최초 출시는 현재 워크스페이스의 최근 이력만 제공한다. 전체 디스크의 오래된 transcript를 무제한 탐색하거나 다른 프로젝트를 한 화면에 합치지 않는다.

## 실행 동작

- 실행 중인 카드: 정확한 live workspace/runtime/pane/session을 재검증한 뒤 `현재 세션으로 이동`한다.
- 종료됐지만 native resume 가능한 카드: 기존 `ResumeAgent`/`RespawnArchivedAgent` 판정과 dotenv 검증을 재사용해 `이어서 실행`한다.
- native resume가 지원되지 않거나 메타데이터가 없으면 사유를 한 줄로 표시하고 `새로 실행`을 제공한다. 새로 실행은 기존 런처를 해당 agent kind로 미리 선택해 연다.
- 과거의 특정 중간 턴으로 되감아 실행하지 않는다. `이어서 실행`은 그 agent session의 최신 상태를 재개한다.
- `Git 변경 보기`는 별도의 Git 구현을 만들지 않고 기존 `DiffPanelUi`와 bounded host-I/O 경로를 재사용한다. live session이 없어도 저장된 검증 cwd로 열 수 있게 진입점만 일반화한다.

## 상태·실패 처리

- 첫 진입은 저장된 snapshot을 즉시 표시하고, transcript/branch 갱신은 기존 bounded background worker에서 수행한다.
- 갱신 중에는 기존 목록을 유지한다. 실패하면 목록을 지우지 않고 헤더에 재시도 가능한 오류를 표시한다.
- stale workspace epoch, 사라진 pane, 바뀐 agent session identity는 실행 동작을 거부하고 새 snapshot을 요청한다.
- 중앙 이력 화면이 열려 있어도 활성 workspace runtime event는 `update_hidden`으로 계속 소비한다. 터미널 입력·composer는 이력 화면에서 비활성이다.

## 완료 기준

- 목업 B안처럼 사이드바가 유지되고 중앙 영역에 카드형 이력이 표시된다.
- Claude, Codex, Kimi의 최근 사용자 턴이 공급자 내부 이벤트 없이 정제되어 보인다.
- 재시작 후에도 저장된 최근 이력이 남는다.
- 검색·필터·카드 확장·새로고침·세션 이동·이어 실행/새로 실행·Git 변경 보기가 동작한다.
- 브랜치가 확인된 카드만 branch 배지를 표시한다.
- 전체 앱 테스트, strict Clippy, fmt, diff-check를 통과한다.
