# 비-Tailscale 모바일 접속과 전체화면 세션 디자인

날짜: 2026-08-28

## 1. 목표

Deppy Sijo 모바일 웹을 Tailscale 설치나 공유기 포트 개방 없이 LTE, 5G, 외부 Wi-Fi에서 사용할 수 있게 설계한다. 모바일 사용자는 안전하게 Mac과 페어링하고 워크스페이스와 세션을 선택한 뒤, 선택한 터미널을 모바일 viewport 전체로 열람하고 입력할 수 있어야 한다.

이번 단계의 산출물은 연결부터 사용·복구까지 보여주는 독립 실행형 HTML 프로토타입이다. 실제 릴레이 서비스, 암호화 프로토콜, 데스크톱 네트워크 경로와 제품 모바일 셸 수정은 후속 구현 범위다.

## 2. 현재 구조와 제약

현재 `web-remote` 서버는 `127.0.0.1` 평문 HTTP로만 바인딩하며, Tailscale Serve가 외부 HTTPS/WSS를 종단한다. 비-loopback 평문 바인딩은 명시적으로 거부된다. QR URL에 포함된 영속 bearer token은 브라우저에서 저장되고 WebSocket 첫 프레임 인증, 업로드, 웹푸시에 재사용된다.

세션 화면은 이미 다음 기능을 지원한다.

- 영속 세션 UUID를 이용한 watch/unwatch
- keyframe과 delta viewport 스트리밍
- 특수키, 한글 IME composer, 첨부 입력
- 연결 복구 뒤 동일 세션 재시청
- 활성·대기·절전 워크스페이스 표시와 전환

하지만 세션 선택 시 뷰어가 대시보드 중간의 인라인 카드로 열리며, canvas 크기는 폭만 기준으로 계산한다.

## 3. 검토한 접근 방식

### 3.1 권장: 데스크톱 발신형 HTTPS/WSS 릴레이

Mac 앱이 고정 HTTPS 릴레이로 outbound WSS 연결을 생성한다. 모바일 브라우저도 같은 릴레이에 HTTPS/WSS로 접속하며, 릴레이는 양쪽 암호화 프레임을 전달한다. 공유기 inbound 포트와 Tailscale 클라이언트가 필요 없다.

장점:

- LTE, 5G, 외부 Wi-Fi를 포함해 어디서든 접근 가능
- 공유기 포트 개방이나 로컬 인증서 설치가 없음
- 고정 HTTPS origin을 사용해 PWA와 웹푸시가 안정적
- 데스크톱 서버의 loopback-only 원칙 유지

비용:

- 릴레이 서비스 운영과 장애 대응 필요
- 공개 인터넷 신뢰경계를 위한 기기별 인증·폐기·감사가 필요
- 릴레이가 내용을 읽지 못하도록 애플리케이션 계층 암호화가 필요

### 3.2 대안: LAN HTTPS 서버

Mac이 사설 네트워크 인터페이스에서 TLS를 직접 종단한다. 같은 Wi-Fi에서는 외부 서비스 없이 동작하지만, iOS와 Android에서 로컬 인증서를 신뢰시키는 절차와 주소 발견이 필요하다. 외부 네트워크에서는 사용할 수 없다.

### 3.3 제외: LAN 평문 HTTP

사설 IP에 평문으로 바인딩하는 방식은 구현이 단순하지만 bearer token과 터미널 권한이 같은 네트워크에서 노출될 수 있다. secure context가 필요한 PWA 기능도 제한되므로 제품 경로로 사용하지 않는다.

## 4. 보안 모델

### 4.1 연결 경계

- Mac과 모바일은 모두 릴레이로 outbound TLS 연결만 생성한다.
- 릴레이는 세션 라우팅에 필요한 최소 메타데이터만 보유한다.
- 터미널 화면, 입력, 승인 내용은 브라우저와 Mac 사이의 애플리케이션 계층 E2EE로 보호한다.
- 기존 loopback 서버를 공개 인터넷이나 평문 LAN에 직접 노출하지 않는다.

### 4.2 페어링과 기기 자격증명

- QR은 5분 만료·일회용 페어링 요청만 포함한다.
- 모바일과 데스크톱 양쪽에 동일한 숫자 확인 코드를 표시한다.
- 데스크톱 승인 후 모바일 기기별 자격증명을 발급한다.
- 영속 전역 bearer token을 공개 릴레이 인증으로 재사용하지 않는다.
- 기기별로 만료, 마지막 접근 시각, 개별 폐기를 지원한다.

### 4.3 권한

각 기기는 다음 권한을 독립적으로 가진다.

- 화면 보기
- 터미널 입력
- 승인 요청 처리

기본값은 화면 보기만 허용한다. 입력과 승인 처리는 데스크톱에서 명시적으로 추가한다. 프로토타입은 권한 선택과 보기 전용 상태를 시각화한다.

## 5. 사용자 시나리오

### 화면 1: 모바일 접속 활성화

데스크톱 설정에서 모바일 접속을 켠다. 앱은 “인바운드 포트를 열지 않고 이 Mac에서 암호화 연결을 시작한다”고 설명한다. 연결된 기기 수와 관리 진입점을 함께 표시한다.

### 화면 2: 보안 릴레이 연결

`인터넷 확인 → 릴레이 연결 → 암호화 채널 준비` 진행 상태를 보여준다. 실패 시 DNS/TLS 문제, 릴레이 장애, 로컬 자격증명 오류를 구분하고 취소·재시도를 제공한다.

### 화면 3: 새 기기 페어링

5분 만료 일회용 QR, 남은 시간, 취소와 재발급을 표시한다. QR이 기존 터미널 권한 bearer token이 아니라 일회성 페어링 요청임을 명시한다.

### 화면 4: 상호 확인과 권한 승인

모바일과 데스크톱에 동일한 확인 코드와 기기 이름을 표시한다. 데스크톱에서 화면 보기, 입력, 승인 처리 권한과 접근 기간을 선택한다. 거부·만료 시 모바일은 새 QR 스캔으로 복구한다.

### 화면 5: 모바일 세션 선택

상단에는 Mac 연결 상태, 종단 간 암호화, 현재 권한을 표시한다. 본문은 워크스페이스별 세션, 에이전트, 실행 상태를 표시한다. 비활성 워크스페이스 전환은 데스크톱 화면도 바뀐다는 확인을 거친다. 승인 요청은 세션 선택과 분리된 탭으로 둔다.

### 화면 6: 전체화면 터미널

세션 선택 즉시 대시보드를 숨기고 모바일 viewport 전체를 사용하는 터미널 화면으로 전환한다.

- 상단: 뒤로, 워크스페이스·세션명, 연결 상태, 권한 상태
- 중앙: 남은 폭과 높이에 맞춘 terminal canvas
- 하단: safe-area 위 특수키 행과 composer
- 보기 전용: 입력 UI를 잠그고 입력 권한 요청만 제공
- 연결 끊김: 마지막 화면을 유지하고 조작을 잠그는 복구 overlay

브라우저 Fullscreen API를 기본 동작으로 사용하지 않는다. 일반 브라우저는 브라우저가 제공하는 viewport 전체를 채우고, 설치형 PWA는 standalone 창 전체를 채운다.

### 화면 7: 중단과 복구

원인별로 다음 행동을 제공한다.

- 네트워크·릴레이 장애: 다시 연결
- Mac 종료·절전: Mac을 켠 뒤 다시 시도
- 권한 만료·기기 폐기: 다시 페어링
- 세션 종료·선택 세션 소멸: 세션 목록으로
- 다른 기기가 제어 중: 보기 전용 유지 또는 제어권 요청

작성 중 draft는 보존하되 연결 복구 후 자동 전송하지 않는다.

## 6. 전체화면 UI 상태 계약

기존 `viewer.watching`을 선택 상태의 단일 진실 소스로 유지한다.

진입 시:

- `body.viewer-open`을 설정하고 배경 대시보드를 `inert`와 `aria-hidden`으로 비활성화한다.
- History entry를 추가해 모바일 Back이 앱을 이탈하지 않고 세션 목록으로 돌아가게 한다.
- focus를 뒤로 버튼 또는 composer로 옮긴다.
- 기존 `watch` 메시지를 전송한다.

종료 시:

- Back, 닫기, `popstate`, 세션 소멸을 하나의 종료 함수로 수렴한다.
- `unwatch`를 보내고 배경 접근성과 스크롤을 복구한다.
- 이전 세션 보기 버튼으로 focus를 돌린다.

레이아웃:

- 뷰어는 `position: fixed`, `inset: 0`, `height: 100dvh`를 사용한다.
- 상·하단 safe-area inset을 반영한다.
- terminal canvas는 가용 폭과 상·하단 제어를 제외한 가용 높이를 함께 사용해 cell 크기를 결정한다.
- `visualViewport.resize`를 우선 사용하고 미지원 환경은 window resize로 폴백한다.

## 7. 프로토타입 범위

독립 실행형 HTML 하나에 다음 인터랙션을 포함한다.

- 데스크톱 설정과 모바일 화면을 나란히 또는 기기 프레임으로 전환
- 연결 진행 상태
- QR 페어링과 확인 코드
- 권한 선택
- 워크스페이스·세션 목록
- 세션 선택 후 full-viewport terminal
- Back, 연결 끊김, 재연결, 세션 종료 상태

프로토타입은 실제 네트워크, 카메라, QR 스캔, 인증, WebSocket 또는 터미널 backend에 연결하지 않는다. 모든 상태는 로컬 JavaScript로 시뮬레이션한다.

## 8. 제품 구현 경계

HTML 프로토타입 승인 후 제품 구현은 두 작업으로 분리한다.

1. 모바일 셸 전체화면 전환: `index.html`, `app.css`, `app.js`만 변경하며 기존 서버·프로토콜을 재사용한다.
2. 비-Tailscale 릴레이: 별도 릴레이 계약, 기기 identity, E2EE, 권한·폐기 persistence, 데스크톱 outbound transport를 설계·구현한다.

두 작업은 독립적으로 배포할 수 있다. 전체화면 UI는 Tailscale 경로에서도 먼저 제공할 수 있다.

## 9. 오류 처리와 개인정보

- 재연결 중 terminal 입력과 특수키를 잠그고 draft를 보존한다.
- 입력을 자동 재전송하지 않는다.
- 앱 백그라운드 전환 시 terminal 내용을 가리는 privacy curtain을 제공한다.
- 감사 로그에는 기기, 세션 식별자, 행위 종류, 시각만 기록한다.
- 토큰, 입력 내용, 터미널 출력은 로그에 기록하지 않는다.
- 프로토콜 버전 불일치는 기존처럼 셸 새로고침 또는 업데이트 안내로 복구한다.

## 10. 검증 계획

이번 프로토타입 단계에서는 사용자 요청에 따라 자동 테스트와 브라우저 테스트를 실행하지 않는다. 제품 구현 단계에서는 다음 검증이 필요하다.

- iOS Safari와 standalone PWA의 세로·가로 화면
- Android Chrome과 설치형 PWA
- 소프트 키보드 열기·닫기와 `visualViewport`
- 브라우저 Back과 focus 복구
- 연결 중단·재연결·Mac 절전
- 선택 세션 종료와 워크스페이스 전환
- 보기 전용·입력·승인 권한 조합
- 일회용 페어링 만료와 기기별 폐기
- 릴레이가 평문 terminal payload를 관찰할 수 없는지 검증
