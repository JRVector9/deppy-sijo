# 기존 터미널 레이아웃을 창 너비에 맞춰 표시

사용자 확정 요구: 창 크기를 바꿔도 기존 글의 형태를 유지하고, 넘치는 부분을 가로로 이동해서 보지 않고 한 화면 너비 안에 표시한다. 별도 PR로 진행하며 앱 재빌드·재실행은 계속 대기한다.

## 결정

- 표시한 세션의 논리 열 수를 유지한다. 새 열 수로 다시 줄바꿈하지 않으므로 기존 표와 줄바꿈이 유지된다.
- pane이 논리 그리드보다 좁으면 터미널 내용만 가로·세로 같은 비율로 축소한다. 다시 넓히면 설정된 폰트 크기까지 돌아온다. 가로 스크롤은 추가하지 않는다.
- 전체 앱 UI 배율과 사용자 폰트 설정은 변경하지 않는다. 매우 좁은 창에서 글자가 작아지는 것은 이 요구의 필연적 결과다. 세로 스크롤백은 기존대로 동작한다.
- 열 수의 우선순위는 이미 전송한 Resize의 열 수 → 표시 중 snapshot의 열 수다. 둘 다 없으면 첫 실제 snapshot을 기다린다. MuxUpdated가 Viewport보다 먼저 와도 추측한 폭이 복원 기록을 다시 줄바꿈하지 않게 한다. 전송 직후 아직 옛 snapshot이 보이는 동안 크기가 되돌아가는 경합도 피한다.
- 새 세션도 backend가 시작한 실제 열 수(현재 기본 80열)를 유지한다. 창을 넓혔을 때 설정 폰트 크기로 복귀한 뒤 남는 오른쪽 공간은 여백이 된다. 최초 화면 gate가 같은 프레임 후반에 열리면 repaint를 예약해 다음 프레임에 행 크기를 조정한다.
- 행 수는 축소된 셀 높이와 pane 높이로 계산하고 기존 3~200행 한계를 유지하면서 런타임의 전체 65,536셀 상한도 함께 적용한다. 이 상수는 runtime에서 공개해 동일 값을 참조한다. 같은 높이에서 폭을 줄이면 표시 행 수와 셀 작업량이 늘 수 있으나 200행 상한을 넘지 않는다. PTY와 backend에는 같은 논리 크기를 보낸다. active TUI에도 같은 논리 폭과 행 변경을 전달한다.
- 저장 형식, wire, Alacritty reflow 구현, 메모리 상한은 변경하지 않는다. 기존 디바운스·resize fence·재시도·롤백·분할 확정 경로를 사용한다.

## 대안 검토

- 새 창 너비로 재줄바꿈: 글자 크기는 유지하지만 표의 원래 행 모양을 보존하지 못한다.
- 고정 폭+가로 스크롤: 형태는 보존하지만 사용자가 제외했다.
- 고정 폭+균일 축소: 형태와 전체 너비 표시를 함께 만족하므로 채택한다.

## 렌더링과 입력 좌표

글리프만 가로로 압축하지 않는다. 원본 셀·글리프·배경·밑줄·선택·커서·IME 조합 표시를 같은 비율로 변환한다. 배경·선택·커서·preedit은 renderer 자신의 shape 구간만 변환하고 pane 배경과 이웃 위젯은 화면 좌표에 남긴다. 캐시된 글자는 축소 갤리로 화면 좌표에 직접 발행하고 실제 ShapeIdx를 구간 변환에서 제외해 이중 축소를 피한다. clip은 화면 clip의 역변환으로 설정한 뒤 shape와 함께 변환한다. font_size를 계속 바꾸지 않아 원본 행 캐시와 폰트 아틀라스를 유지한다. text run마다 최근 배율의 축소 갤리 하나만 캐시해 같은 배율 재그리기에서 깊은 복제를 피한다. 배율 변경 시 교체하고 1배로 복귀하면 버린다. 축소 중에는 원본과 축소본을 함께 보관하는 메모리 비용이 있으며 드래그처럼 배율이 달라지는 프레임의 복제는 남는다. 작은 배율에서의 텍스처 재샘플 가독성은 화면 검증 대상으로 남긴다. hit-test 영역, RenderOutput의 origin/cell_size, IME 후보창 좌표는 실제 화면 좌표를 사용한다. 휠과 드래그 자동 스크롤도 화면에 보이는 셀 높이를 기준으로 환산한다. 새 프레임의 IME 소유권 계약은 별도 PR #147과 충돌 없이 유지한다.

## 검증

크기 요청 경로의 회귀는 테스트를 먼저 추가해 기존 코드에서 실패를 확인한다. 최종 커밋 전 관련 workspace/terminal 테스트, fmt, scoped clippy, diff-check를 실행한다. 앱 검사는 반드시 --bin deppy-sijo, terminal은 --lib로 제한해 실행 앱 바이너리를 갱신하지 않는다. 실제 화면의 가독성과 타이핑은 재실행 승인 후 검증하며 현재 PASS로 표시하지 않는다.
