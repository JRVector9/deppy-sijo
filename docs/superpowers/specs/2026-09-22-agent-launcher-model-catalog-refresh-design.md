# 에이전트 런처 모델 카탈로그 자동 갱신 설계

## 목표

Grok CLI가 새 모델을 로컬 카탈로그에 반영한 뒤에는 Deppy Sijo를 재시작하거나 런처의
새로고침 버튼을 누르지 않아도, 다음에 에이전트 런처를 열 때 새 모델이 선택 목록에
나오게 한다. 같은 갱신 경로를 사용하는 Codex·Kimi·Qwen Code의 동적 카탈로그에도 이
동작을 일관되게 적용한다.

## 현재 원인

모델 파서는 이미 `~/.grok/models_cache.json`의 object/info 형식을 읽고 모델 ID, 표시
이름, 지원 추론 강도와 기본 강도를 동적으로 만든다. 실제 Grok 1.0.40 카탈로그에도
`grok-4.7`과 `grok-4.7-build-fast`가 정상 저장돼 있다.

문제는 파싱 이후의 수명주기다. 앱은 시작 시 `agent_launcher_snapshot`을 한 번 만든다.
그 뒤 런처를 열 때 snapshot이 없는 경우에만 탐지 worker를 다시 요청하므로, 실행 중
CLI 카탈로그가 갱신돼도 기존 snapshot을 계속 표시한다. 수동 새로고침은 같은 worker를
다시 실행하므로 새 모델을 표시하지만 자동 반영은 하지 않는다.

## 선택한 방식

런처를 열 때마다 `agent_launcher_detection_requested`를 설정한다. 기존 snapshot은 즉시
표시하고, 파일 읽기와 파싱은 기존 `LazyBoundedWorker`에서 수행한다. 결과가 도착하면
현재와 같은 단일 교체 경로로 snapshot을 바꾼다.

이 방식은 런처가 열리는 사용자 동작을 갱신 시점으로 삼는다. 매 프레임 파일 상태를
조회하거나 상시 watcher·주기 timer를 추가하지 않는다. Deppy가 Grok 서버에 직접
접속하거나 `grok models` 프로세스를 실행하지도 않는다. 모델 배포와 인증은 각 CLI가
소유하고, Deppy는 CLI가 안전하게 기록한 로컬 카탈로그를 읽는 기존 경계를 유지한다.

## 사용자 동작

1. 사용자가 런처를 연다.
2. 기존 snapshot이 있으면 설치된 에이전트와 모델을 즉시 보여준다.
3. 동시에 기존 bounded worker에 최신 감지를 요청한다.
4. 완료되면 열린 런처의 모델 목록이 새 snapshot으로 갱신된다.
5. 사용자가 고른 에이전트와 모델이 새 목록에도 있으면 선택을 유지한다.
6. 설정 파일의 기본 모델도 그대로 존중한다. 새 버전이 나왔다는 이유만으로 기본값을
   최신 모델로 바꾸지 않는다.

동일한 요청이 이미 실행 중이면 기존 in-flight gate가 중복 실행을 막는다. 사용자가
런처를 빠르게 닫아도 완료 결과는 다음 열기에 사용할 최신 snapshot으로 남는다.

## 오류 처리

- 카탈로그 파일이 없거나 손상되면 기존 내장 목록 폴백을 유지한다.
- worker 제출이 일시적으로 Full이면 `detection_requested`를 유지해 다음 logic tick에서
  다시 시도한다.
- worker 자체가 실패하면 이미 표시 중인 snapshot을 버리지 않는다. 런처가 열려 있으면
  기존 감지 실패 표시를 사용한다.
- 카탈로그 항목 수·문자열 길이·제어문자·숨김 모델 필터 등 현재 입력 상한을 유지한다.

## 테스트

- RED: snapshot 존재 여부와 관계없이 런처 open 경로가 재감지를 요청해야 한다.
- GREEN: 활성 워크스페이스 런처와 다른 워크스페이스에서 전환 후 여는 경로가 모두 같은
  open 동작을 사용한다.
- 기존 Grok object 카탈로그 파서 테스트에 4.7 및 4.7 Fast 형태를 넣어 모델과 추론 강도
  자동 수용을 확인한다.
- 기존 런처 선택 조정 테스트로 갱신 뒤 유효한 현재 선택과 설정 기본값이 유지되는지
  확인한다.

## 범위 밖

- Grok 모델을 Deppy 내장 목록에 매 릴리스마다 하드코딩하지 않는다.
- 새 모델을 자동으로 기본 선택하지 않는다.
- 원격 모델 API 직접 호출, 인증 정보 접근, 상시 파일 watcher, 주기 polling을 추가하지
  않는다.
- 이번 작업에서 앱을 재빌드하거나 재실행하지 않는다. 별도 사용자 요청 시 수행한다.
