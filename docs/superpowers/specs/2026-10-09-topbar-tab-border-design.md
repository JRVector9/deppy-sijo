# 탭바 선택·구분선 — 승인됨

사용자 요청: 탑바의 선택된 항목은 상단선과 우측선만 강조하고, 선택되지 않은 항목은 연한 선으로 구분한다. 먼저 HTML 시안을 제시한다.

시안: `docs/mockups/topbar-tab-border-2026-10-09.html`. 사용자가2026-10-09에 “이대로 구현해”로 승인했다. 소스 구현과 검증을 진행하며 제품 빌드 전달·앱 재실행은 이번 요청 범위에 없다.

적용 완료: `crates/app/src/ui/workspace.rs`에서 공통 `paint_tab_lines`를 사용한다. 선택100%는 기존 pane 기본 선 색을 기준으로 하며 기존 워크스페이스 채도·포커스 색 정책은 유지한다. 실제 실행 검증은 기존 탭 검사10개와 App2809개(38 ignored), strict App Clippy·fmt·boundary 모두PASS, 직접 소스 리뷰OK다. 상세 결과와 명령은 `docs/superpowers/plans/2026-10-09-topbar-tab-border.md`에 기록했다.

## 공통 규칙

- 세션·이력·Git·문서 모두 같은 탭 상태 규칙을 사용한다. 색은 pane의 워크스페이스 색 하나를 공유한다.
- 각 탭은 자기 영역의 상단선과 우측선만 가진다. 좌측선과 하단선은 없고, 탭 뒤의 빈 영역에는 선을 연장하지 않는다. 경계는 앞 탭의 우측선 한 번만 그린다.
- 선택 선은 기본색100%, 비선택24%, 비선택 hover36%다. 선택 hover는100%를 유지한다. 제목은 선택 시 밝은 기본 텍스트, 비선택 시 muted, hover 시 기본 선택 라인과 같은 색이다.
- 높이27px, 선 두께1px, 상태별 농도를 공통 변수로 둔다. 현재 제품의27pt 기준을 유지하며 선택·hover로 크기를 바꾸지 않는다. 화면 밀도는 실제 구현 시 egui 픽셀 스냅 규칙에 맞춘다.
- 긴 제목은 한 줄 말줄임, 닫기 히트박스는 보존한다. 닫기 hover와 탭 선택 상태는 독립이다. 키보드 focus-visible의 점선 표시는 탭 선택 라인과 별개다.

## 현재 코드와 후속 적용 범위

현재 `crates/app/src/ui/workspace.rs`의 `paint_pane_header_base`는 선택 상단선을 그리지만 `paint_tab_divider`는 세션 우측 경계를 pane 포커스 스타일로 별도 강조한다. 보조 탭은 같은 우측선을 소유하지 않아 선택 위치와 강조 경계가 어긋날 수 있다.

선택된 항목을 결정하는 기존 상태를 유지하면서 세션/보조 탭/세션 없는 스트립과 단일 attached 헤더에 공통 선 규칙을 적용한다. 비포커스 pane은 기존 pane 스타일의 기본 선 색을 유지하고, 선택100%/비선택24%/hover36% 비율을 동일하게 사용한다. 따라서 pane 포커스와 탭 선택을 별개의 상태로 유지한다. 세션 추가 빈 영역·닫기·본문 라우팅은 기존 기능 계약을 유지한다.

## 시안 확인

클릭 가능한 탭, 좌우/Home/End 키, Delete 닫기, 초기화,1배/2배 보기와 워크스페이스 색 비교를 제공한다. 정적 예제4개로 각 선택 위치의 실제27px 줄을 보여준다. 실제 앱과 연결하지 않는 예시이며 앱 구현 완료를 뜻하지 않는다.
