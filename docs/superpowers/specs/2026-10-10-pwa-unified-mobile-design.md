# PWA 통합 입력과 모바일 화면 수정 시안

상태: 2026-10-10 사용자 승인. 시안대로100% 구현, PR 단위 계획 및 gpt-6.1-sol/xhigh 서브에이전트 병렬 작업. 추가 스킬 사용 금지.

HTML: ../../mockups/pwa-mobile-unified-input-2026-10-10.html

## 요청과 확인된 원인

- 상단 과거 열람 안내 대신 맨 아래 스크롤 동작만 제공한다.
- 과거 내용 조회량을 늘리고 터미널이 가용 세로 영역을 채운다.
- 워크스페이스를 모바일에 맞춰 다시 구성한다.
- 터미널/작성 모드를 없애고 한 입력창을 사용한다.

현재0.9.0 코드에서 확인한 사항:

- `web/shared/viewer-core.css:26,94`: 안내 바를 별도44px 행으로 이동하며 hidden일 때도 visibility만 끈다. 최신 출력 상태에서도 이 공간이 남는다.
- `crates/terminal/src/alacritty_backend.rs:650`: 독립 이력 조회도 `grid.screen_lines()`만큼 반환한다. `TerminalHistoryQuery`에는 휴대폰 표시 행 수가 없다. `web/shared/viewer-core.js:885`는 수신 행 수×셀 높이로만 출력 높이를 만든다. 따라서 휴대폰이 더 높을 때 남는 공간을 과거 내용으로 채우지 못한다. 이는 저장된 전체 이력이 없다는 뜻이 아니다.
- `crates/web-remote/assets/app.css:263–280`: 세션을 작은 인라인 칩으로 표시하며 제목11px, 상태10px, 에이전트 숨김을 적용한다. 목록이 모바일에서 읽고 누르기 어렵다.
- `crates/web-remote/assets/app.js:956,1162–1165,1538`: 두 입력 경로와 모드별 활성 조건을 둔다. 이전 PR2에서 즉시 키 입력과 전송 전 초안을 구분하려던 결정이나, 사용자는 모드 전환 없이 한 입력창을 원한다.

현재 보고는 코드와 HTML 시안 관찰의 근거다. 실제 연결된 iPhone/Safari의 표시 공간·키보드·실제 출력 조회량을 측정한 결과로 확대하지 않는다.

## 선택한 구성

전체 높이 터미널 + 하단 통합 입력을 사용한다. 워크스페이스는 그룹별 전체 폭 행 목록으로 구성한다. 별도 작성 화면과 모드 버튼을 제거한다.

검토한 대안: 모든 입력을 즉시 PTY에 보내면 긴 문장을 보내기 전에 수정하기 어렵고 붙여넣기/IME 확정 처리가 까다롭다. 별도 전체 화면 작성기는 요청한 통합 흐름과 맞지 않는다. 기본 입력창에서 문장을 편집하고 명시적으로 전송하며, Ctrl/방향키 등의 제어 키는 같은 입력창 옆 보조 키로 제공하는 구성을 선택했다.

## 화면 규칙

- 헤더와 입력창을 제외한 가용 높이는 터미널이 차지한다. 설치 PWA safe-area와 visualViewport를 사용하고 키보드 변화는 출력 삭제나 PTY 강제 resize로 처리하지 않는다.
- 상단 이력 안내 바와 항상 비워 두는44px 행을 제거한다. 최신 출력에서 떨어졌을 때만 터미널 우측 하단에 `↓ 맨 아래로` 버튼을 표시한다. 버튼은 최신 출력으로 이동하고 이후 출력을 따라간다. 이력 조회·만료 오류는 설정/필요한 비차단 안내로 처리한다.
- 한 입력창은1줄/44px에서 시작해 최대5줄로 늘어난 뒤 내부 스크롤한다. 글자16px, Enter 전송/Shift+Enter 개행; IME 조합 중 Enter는 전송하지 않는다. 모바일 키보드 개행과 명시적 전송 버튼을 지원한다.
- 보조 키는 같은 입력창 옆 펼침 버튼으로 제공한다. 첨부도 같은 입력창에 경로를 삽입한다. 긴 입력도 동일 세션/동일 전송 확인 경로를 사용한다.
- 워크스페이스 이름15px, 세션 제목14px/최대2줄, 에이전트·상태12px. 세션 전체 행이 최소76px 터치 영역이다. 활성 워크스페이스를 기본 펼치고 나머지는 접는다. 이름·경로·세션 제목·에이전트 검색 시 일치 세션을 펼친다.
- 실제 활성 상태만 현재 상태로 표시한다. 대기/절전 워크스페이스의 저장 상태를 실시간 에이전트 활동으로 꾸미지 않는다. 비활성 워크스페이스의 세션을 선택하면 Mac 워크스페이스도 전환된다는 동작을 안내한다.
- 상단 세션 선택은 전체 제목과 상태를 볼 수 있는 하단 목록으로 제공한다. 세션 초안과 읽던 위치는 세션별로 유지한다. 글자 크기/읽기 줄바꿈/크기 제어 등 설정은 큰 터치 영역의 하단 패널로 구성한다.

## 제품 구현 시 기술 범위

1. 서버 이력 조회를 실제 표시 행 수와 독립적인 유계 구간 조회로 확장한다. 실화면과 이력 구간을 구분하며 PTY rows, cursor, native scroll, alternate screen은 유지한다. 표시를 위해 셀 간격을 늘리거나 Mac 터미널 행 수를 임의 변경하지 않는다.
2. 기본 조회량을 가용 높이/셀 높이로 계산하고 앞뒤 여유 구간을 받아 스크롤 시 연속 연결한다. 메모리/셀/전송 크기를 제한하며 부족한 저장 이력을 만들어내지 않는다. 구현 계획에서 구간·캐시 상한을 확정한다.
3. stable generation/first_line/request, 최신 시청 세대, 이력 trim/만료, 재연결 처리와 기존 세션별 보존을 유지한다. 늦은 조회 응답이나 새 출력이 읽던 화면을 덮지 않는다.
4. 입력 모드 조건과 두 DOM 입력창을 통합한다. IME, 한글 경로 NFC, 큰 붙여넣기, bounded send/ACK, 세션 전환·종료·재연결 때 전송 거절과 초안 보존을 회귀 검증한다. 작성 도중 특수키를 눌렀을 때의 입력 순서를 명확히 유지한다.
5. 루프백/Relay 공용 코어와 셸을 함께 점검한다. Relay의 기존 권한을 확대하지 않는다. 지원하지 않는 쓰기 기능을 버튼으로 제공하지 않는다.

## 시안 검증과 실제 검증 구분

HTML은 예시 출력과 로컬 입력만 사용하는 디자인 시안이다. 과거 내용은 예시300여줄이며 서버 조회/실제 PTY를 구현한 증거가 아니다. 키보드는258px 가상 표시다. 검색·세션 선택·입력 확장·스크롤·맨 아래 이동의 표시 동작을 확인한다.

제품 구현의 합격 기준은320×568/390×844/844×390, 큰/작은 native PTY 행 수, 연속 이력/trim/alternate screen, 키보드 열림과 입력 확장, 긴 한글 입력/세션 변경/재연결, 워크스페이스 상태 및 루프백/Relay 계약 회귀다. 실기기 미검증은 별도 기록한다. 제품 적용 전 설계를 확인하고 다음 구현 계획을 작성한다.
