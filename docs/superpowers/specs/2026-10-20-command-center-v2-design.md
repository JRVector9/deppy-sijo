# 1안 발전형 — 프로젝트 지휘 터미널

2026-10-20. 사용자가 기존 Codex 1안의 세 영역 구성을 선택하고 그 방향에서 발전시키도록 요청했다. 제품 구현 요청으로 확대하지 않고 새 HTML로 구체화한다. 기존 1안과 추천 결합안은 보존한다.

시안: `docs/mockups/multi-agent-command-center-v2-2026-10-20.html`

## 채택한 구조

- 왼쪽: 여러 프로젝트와 각 프로젝트의 독립 작업 세션을 탐색한다. 프로젝트를 누르면 해당 메인으로, 세션을 누르면 정확한 프로젝트/작업으로 이동한다.
- 중앙: 프로젝트 목표 → 메인의 역할별 배정 → 진행 취합 → 승인/결과 확인. 메인과 선택 작업자의 입력 대상이 명시된다.
- 오른쪽: 현재 프로젝트 작업자만 지속 관측한다. 역할/상태/범위/최근 내용/기기/예시 관측 시각을 보며 정확한 작업 상세·승인·결과·원문 터미널로 이동한다. 전체/확인 필요/실행 중 필터와 실행 규칙/기기 관리 진입을 제공한다.
- 상단: 메인 에이전트/작업/터미널/에이전트·기기/이력. 프로젝트 이름과 경로·설정은 작업 영역 위에서 유지한다.

## 이전 시안에서의 발전

1. 1안의 세 영역과 오른쪽 작업자 관측을 복원했다. 중앙의 작업 목록 중복을 줄이고 목표·배정·메인 진행 대화에 집중한다. 왼쪽은 프로젝트 탐색, 오른쪽은 현 프로젝트 관측으로 구분한다.
2. 추천안의 요청별 세 역할 배정, 기기 선택, 검증 선행 관계, 독립 초안, 오프라인 배정 차단을 유지한다. 동일 문장도 신규 목표로 처리한다.
3. 작업 안의 정확한 명령/폴더/기기 승인, 결과 제출과 사용자 확인 분리, Git diff·작업별 기록, 프로젝트 실행 규칙, 컴퓨터·휴대폰 연결을 유지한다.
4. 넓은 화면은 세 영역, 1050px 이하에서는 작업자 버튼으로 우측 패널을 연다. 760px 이하에서는 좌측도 펼침 방식이며 양 패널을 동시에 열지 않는다. 휴대폰은 같은 본문·입력을 사용한다. 우측 패널 접기는 데스크톱에서 가능하며 1안의 다크/라이트 전환을 유지한다.

## 데이터와 상태 원칙

프로젝트 전환은 이전 메인/작업 초안을 저장한 뒤 대상을 바꾼다. 오른쪽은 현 프로젝트의 task ID만 조회한다. 설정은 새 배정에 적용하고 기존 작업 폴더/담당 snapshot은 유지한다. 승인 수용은 실행 시작 또는 성공이 아니며 검증은 선행 결과를 기다린다. 결과 수신과 사용자 확인을 구분한다. 기기가 연결되지 않았으면 기존 결과를 보존하고 직접 입력을 막으며 기기 연결 끊김을 별도로 표시한다.

모든 계획·기기·코드·출력·승인·Git·결과·시각은 메모리 fixture이다. 실제 AI/PTY/SSH/인증/파일/테스트 실행 또는 영구 저장과 연결되지 않는다. 새로고침 초기화. 이 HTML은 제품 기능 구현·성능·실시간 상태 검증이 아니다.

## 검토 범위와 다음 단계

이번 산출물은 독립 HTML과 디자인/QA 문서다. 제품 Rust·Cargo 변경, 앱 빌드·재시작·버전 갱신·자동 커밋은 없다. 제품 구현으로 진행할 때 기존 6PR의 identity/persistence/dispatch/orchestration/device/권한/harness 계약을 먼저 재검토하며, UI의 fixture 객체를 DB schema로 취급하지 않는다.
